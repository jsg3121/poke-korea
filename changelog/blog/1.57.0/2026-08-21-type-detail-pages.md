# 타입별 상성 상세 페이지 18개 신설

> **작업 날짜**: 2026-08-21
> **브랜치**: `feature/1.57.0-type-detail-pages`

## 📋 작업 개요

**작업 유형**: 기능 추가 / SEO
**담당**: jsg3121, claude

## 🎯 작업 목표

`/type-effectiveness` 한 페이지가 감당하던 검색 의도를 18개 하위 페이지로 나눈다. 계산기 의도는 그대로 두고, 약해진 "타입별 약점·상성" 의도를 되받는 것이 목표다.

<!-- truncate -->

## 📉 왜 만들었나

Search Console 20일 비교(7/8~7/27 vs 7/28~8/16)에서 이 페이지가 크게 빠졌다.

| 지표 | 이전 | 이후 | 변화 |
| --- | ---: | ---: | ---: |
| 노출 | 202,610 | 90,984 | **-55.1%** |
| 클릭 | 11,577 | 8,612 | **-25.6%** |
| 평균 순위 | 6.57위 | 5.72위 | 0.85위 개선 |

순위는 오히려 좋아졌는데 노출이 반토막 났다. 검색어별로 보면 원인이 갈린다.

```text
포켓몬 상성 계산기   클릭 -11.9%  순위 1위 유지   ← 견고
포켓몬 상성          클릭 -36.8%  (891클릭 손실)  ← 약화
포켓몬 상성표        클릭 -32.5%
포켓몬 타입          클릭 -64.7%  순위 5.70→7.24
악타입 약점          노출 -83.7%                  ← 롱테일 붕괴
전기 약점            노출 -87.0%
```

계산기 의도는 멀쩡하고 **정보형 의도가 무너졌다.** 3주간 회복이 없어 관찰을 종료하고 대응에 들어갔다.

## ✨ 주요 변경사항

### 변경 1: `/type-effectiveness/[type]` 18개 라우트

`독타입 약점`으로 들어온 사용자가 **스크롤 없이 약점을 확인**하는 것이 이 페이지의 존재 이유다. 폴드에 Breadcrumb → H1 → 리드 → 약점 즉답 카드 → 고유 사실을 넣고, 광고는 폴드에 두지 않았다.

블록 구성은 검색 의도 충족 속도 순이다.

```text
1. 약점 즉답 (타입 배지)
2. 방어/공격 상성 전체
3. 복합 타입 사례 + 고유 효과
4. 타입별 포켓몬 6종
5. 대전에서 쓰이는 타입 (챔피언스 티어)
6. FAQ
7. 계산기·퀴즈 CTA + 다른 타입 링크
```

### 변경 2: 복제 페이지가 되지 않게 하는 장치 4종

18개를 한 번에 만들면 "타입명과 배율만 바뀐 얇은 페이지"가 되기 쉽다. 이번 작업의 가장 큰 리스크였다.

**① 고유 콘텐츠 상수** — 타입마다 고유 사실·FAQ 3문항·실존 복합 타입 3종을 직접 썼다. 자동 생성하면 18개 문장 구조가 같아져 원래 문제로 돌아간다.

**② 인지도 상위 포켓몬 108종** — 페이지마다 등장 포켓몬이 100% 다르다. `types[0]` 기준으로 분류해 한 종이 여러 타입에 중복 노출되지 않게 했다.

**③ 챔피언스 티어 블록의 조건부 렌더** — S·A·B 티어가 없는 포맷은 줄이 생략되고, 둘 다 없으면 섹션이 사라진다. 실제로 독 타입은 BSS에 해당 티어가 없다.

**④ 출시 전 자가검증** — 18개 페이지 153개 쌍의 본문 어휘 차이를 실측했다. UI 공통 문구를 제외하고 평균 82.4%, 고유 사실 18개·FAQ 질문 54개가 전부 다른 것을 확인했다.

### 변경 3: 검증 가능한 사실만 서술

초안 FAQ에는 "강철은 금속이라 독이 스며들지 않는다는 설정", "2세대에서 에스퍼가 강해서 악이 추가됐다" 같은 서술이 있었다. **공식 근거가 없는 통념**이라 전부 걷어냈다.

질문도 "왜 ~인가요"에서 "무엇/몇 개인가요"로 바꿔 검증 가능한 답만 나오게 했다. 그 뒤 남은 서술을 상성 계산과 대조해 **오류 9건을 수정**했다.

```text
"에스퍼 무효화는 악과 강철"  → 악뿐 (강철은 0.5배 반감)
"격투가 2배 대상 최다"        → 땅과 동률 5개
"바위/물은 풀·전기 4배"       → 풀만 4배, 전기는 2배
크리만을 악/드래곤 예시로 씀  → 순수 드래곤이라 악식킹으로 교체
```

포켓몬 예시 110종은 GraphQL로 실존과 타입 구성을 전수 확인했다.

### 변경 4: 메인 페이지 보강

**내부 링크 47회** — 각 타입이 최소 2회 링크를 받는다.

- 타입 미선택 시 결과 영역의 빈 공간에 18개 링크(선택하면 사라짐)
- 상성표 행 헤더 18개
- "타입별 추가 효과" 문맥 링크 11개

**title·H1 재설계** — `포켓몬 상성 계산기` → `포켓몬 타입 상성표·상성 계산기`. 잃은 키워드(`상성표`·`타입`)를 앞에 넣되 1위 자산인 `계산기`를 뒤에 남겼다.

## 🔍 구현 중 판단한 것

### 정적 생성을 쓰지 않았다

기획서는 `generateStaticParams`로 18개를 빌드 시 생성하라고 권장했다. 그러나 이 코드베이스는 29개 페이지 전부가 `headers()` UA 감지로 헤더/푸터/탭바를 고르기 때문에 구조적으로 정적 생성이 불가능하다. UX-007/008/009에서 실효 없는 `revalidate` 선언을 "거짓 신호"로 제거한 이력도 있다.

기존 패턴을 따라 동적 렌더로 두고, 사유를 파일 주석에 남겼다. 상성 데이터가 전부 정적 상수라 응답 자체는 빠르다.

### 슬러그 대소문자를 구분했다

초안은 `toLowerCase()`로 관대하게 받았는데, 그 결과 `/water`와 `/WATER`가 **같은 내용을 다른 URL로 서빙**했다. 중복 URL이다. 실제 요청을 보내 확인하지 않았다면 놓쳤을 문제다.

### 포켓몬 목록은 그리드가 아니라 가로 스크롤

데스크톱 본문 폭 1248px에 카드(224px 고정) 6개는 1344px이 필요하다. 6열이면 카드가 칸을 넘어 겹치고, 5열이면 둘째 줄에 1개만 남는다. `HorizontalScrollList` DS로 전환해 카드 고정폭을 지키면서 한 줄에 담았다.

### "대표"라는 표현을 쓰지 않았다

서비스 내부에 인기도 데이터가 없어 6종 선정은 편집 판단이다. "대표"·"인기 순"은 확정된 공식 순위처럼 읽히므로 `널리 알려진 6종`으로 쓰고, 순위 번호도 노출하지 않았다.

반대로 챔피언스 블록은 티어라는 근거가 있어 티어·채택 순위를 명시했다. 다만 `usageRate`가 항상 null이라 사용률(%)은 표기하지 않고 그 사실을 부제에 밝혔다.

## 🔎 SEO 검토에서 확인한 것

구현 후 SEO 검토를 돌려 이중 접미사·h1 중복·canonical 불일치가 없음을 확인했다. 결함은 없었고, 두 가지를 기록해 둔다.

**FAQPage 리치결과는 기대할 수 없다.** Google이 [2023년 8월부터 FAQ 리치결과를 정부·의료 사이트로 제한](https://developers.google.com/search/blog/2023/08/howto-faq-changes)했다. 스키마는 유효하고 화면 콘텐츠와 일치하지만, 검색 결과에 FAQ 아코디언이 노출되지는 않는다. FAQ의 가치는 **사용자가 페이지에서 읽는 답변**에 있다.

**description은 83~98자로 유지했다.** 프로젝트 규약은 120~160자였으나 이는 영문 통설을 옮긴 값이다. 한국어 스니펫은 보통 80자 안팎에서 잘리므로 길이를 채우면 핵심 답이 잘린 뒤로 밀린다. 규약 쪽을 한국어 80~120자로 정정했다.

## ⚠️ 측정에 대한 유의

이번 릴리즈는 **메인 title 변경과 하위 페이지 출시가 함께 나간다.** 따라서 이후 클릭이 회복돼도 어느 쪽 덕인지 분리할 수 없고, 타입 상성 트랙 전체의 합산 성과로 판단하게 된다.

또한 2026년 8월 18일부터 별도 Google spam update가 진행 중이라, 그 이후 데이터는 7/29~8/16 하락 구간과 섞지 않고 별도로 집계해야 한다.
