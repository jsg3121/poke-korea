# ADR 후속 정리 (Phase 2-5)

> **작업 날짜**: 2026-09-21
> **브랜치**: `feature/1.61.0-adr-followup`

## 📋 작업 개요

**작업 유형**: 리팩토링 (구조·네이밍·설정) + 하네스 보강
**담당**: jsg3121, claude

[컨벤션 개편](/convention-overhaul)에서 작성한 ADR-0016~0020이 "후속 정리 대상"으로 남겨둔 코드 변경을 처리한다. [전역 크롬 layout 승격](/layout-chrome)에 이은 Phase 2의 마지막 항목이다.

## 🎯 작업 목표

**문서에만 있고 코드에는 없던 결정을 적용한다.**

ADR은 "이렇게 하기로 한다"까지 적고, 실제 적용은 후속 작업으로 미뤄둔 항목이 있었다. 그 간격을 좁힌다.

먼저 각 항목이 실제로 미적용인지 코드와 대조했다. 기록과 현실이 달랐다.

## ✨ 주요 변경사항

### 변경 1: 폐기된 브레이크포인트 제거 (ADR-0020)

`tailwind.config.js`에서 `desktop-970`·`desktop-639`를 뺐다. 클래스 사용처가 **0건**이라 렌더 결과는 바뀌지 않는다.

`TypeQuickLinks`의 주석에도 이 이름이 남아 있어 함께 정리했다. 존재하지 않는 브레이크포인트를 설명하는 주석은 다음 사람을 오도한다.

### 변경 2: 린트·포맷 설정 도입 (ADR-0019)

| 파일                     | 내용                                              |
| ------------------------ | ------------------------------------------------- |
| `.prettierignore`        | codegen 생성물 제외 — 재생성 시 diff가 튀는 것 방지 |
| `.vscode/settings.json`  | 포매터 고정, 저장 시 ESLint fix                   |
| `.vscode/extensions.json`| Prettier·ESLint 권장 목록                         |
| `package.json`           | `format`·`format:check`·`lint:fix` 스크립트       |

`eqeqeq`는 `{ "null": "ignore" }`를 붙여 켰다. 코드의 느슨한 비교 16건이 **전부 `== null` 관용구**였기 때문이다. 기본값으로 켜면 16건이 모두 에러가 되고 `!== null && !== undefined`로 장황해진다.

```ts
// 이 형태를 유지한다 — null과 undefined를 함께 거른다
if (pokemonId == null) return null
```

규칙이 실제로 동작하는지도 확인했다. `== null`은 통과하고 일반 `==`는 에러가 난다.

### 변경 3: 문서 md를 포맷 대상에서 제외

`format:check`를 처음 돌리니 **117건이 미준수**였다. 전부 재포맷하려다 실제 diff를 확인하고 멈췄다.

```diff
- > **루트 브랜치**: `feature/1.44.0`
- > **포함 PR**: #135 (M4 점검), #136 (애드센스 Phase 1)
+ > **루트 브랜치**: `feature/1.44.0` > **포함 PR**: #135 (M4 점검), #136
```

Prettier가 blockquote 연속 줄을 한 줄로 접는다. **정렬이 아니라 내용 훼손이다.** 과거 릴리즈 노트 여러 건이 같은 패턴이었다.

지침(`.claude/`)과 릴리즈 노트(`changelog/`)의 md는 사람이 쓰는 기록물이라 포맷 통일의 실익이 없다. `.prettierignore`로 제외했다. 나머지 6건(Docusaurus 설정 2건, analyzer 스크립트 3건, README)은 실제 코드·문서라 포맷을 적용했다.

### 변경 4: `IF` 접두사 제거 (ADR-0017)

`naming.md`가 금지하는 접두사가 context 3개 파일에 6건 남아 있었다.

Context 값 타입은 `...Props` 대신 `...ContextValue`로 바꿨다. `createContext<T>`에 쓰이는 타입은 컴포넌트 props가 아니므로, `{컴포넌트명}Props` 규칙을 그대로 적용하면 **이름이 역할을 속인다.**

```ts
// 변경 전 → 변경 후
IFDeviceProviderProps → DeviceProviderProps   // Provider의 props가 맞다
IFDeviceProps         → DeviceContextValue    // props가 아니라 Context 값
```

### 변경 5: Tag 컴포넌트 2벌 통합 (ADR-0016)

같은 이름의 `Tag.component.tsx`가 두 곳에 있었다. `structure.md`가 명시적으로 금지하는 상태다 — 경로만 다르고 이름이 같으면 import에서 구분되지 않는다.

| | 구버전 | 신버전 (DS) |
| --- | --- | --- |
| 스타일 | `globals.css`의 `.type-tag` | Tailwind 토큰 정적 매핑 |
| 사용처 | champions 2곳 | 나머지 18곳 |

신규 파일 주석이 "기존 Tag.component를 대체한다"고 적고 있고, `Tag.stories`가 **"기존 태그는 모든 타입이 검정 글자로 고정되어 6종에서 대비 미달"**이라고 기록해 색상 차이가 의도적 교정임을 밝힌다. 신버전으로 통합했다.

사용처가 0건이 된 `.type-tag`와 `chip-type-*` 18종, 그리고 관련 safelist를 제거했다.

### 변경 6: 도메인 간 참조 정리 (ADR-0016)

`structure.md`의 배치 규칙 — **2개 이상 도메인이 쓰면 전역 폴더** — 를 적용했다.

| 컴포넌트             | 사용 도메인                        | 처리                 |
| -------------------- | ---------------------------------- | -------------------- |
| `ChampionsTopCard`   | champions·home                     | `components/common/` |
| `ChampionsTierBadge` | champions·typeEffectivenessDetail  | `components/common/` |
| `ChampionsSubNav`    | 헤더 desktop/mobile                | **유지**             |

`ChampionsSubNav`를 남긴 이유는 소비처가 **같은 헤더의 두 구현**이라 도메인 1개로 보는 것이 타당하기 때문이다. champions 경로·포맷 상수에 묶인 도메인 지식이기도 하다.

### 변경 7: 통합 브랜치 편집 차단 훅

작업 도중 `feature/1.61.0`에 직접 커밋하는 실수가 났다. 머지 이력에 서브 브랜치 패턴(#229~#232)이 뚜렷했는데도 **그 규칙이 `workflow.md`에 없었다.**

`workflow.md`에 "통합 브랜치와 서브 브랜치" 절을 신설하고, `block-version-root-edit.sh`로 강제한다. `feature/X.Y.Z`에 정확히 일치할 때만 차단하고 `-{주제}`가 붙은 서브 브랜치는 통과시킨다.

## ⚠️ 구현 시 고려한 점

### 화면이 바뀌는 지점

Tag 통합으로 **champions 화면의 태그가 실제로 달라진다.**

- 모바일에서 크기 축소: `w-[3.6rem]`/`h-6` 고정 → `w-12`/`h-5` (desktop은 `w-14`/`h-6`)
- 물·바위 타입 글자색 반전 — WCAG AA 대비 기준에 맞춘 교정

의도된 변화지만 눈으로 확인이 필요하다. `/champions` 티어·토너먼트 화면을 봐주시기 바란다.

### `.vscode/`를 커밋한 판단

`settings.json`만 두면 Prettier 확장이 없는 PC에서 저장 시 포맷이 **에러 없이 조용히 실패**한다. 설정을 공유해 통일하려던 것이 오히려 환경별 불일치를 만든다.

그래서 `extensions.json`을 함께 뒀고, `typescript.tsdk`는 `npm install` 전에 경로가 없어 경고를 띄우므로 뺐다. 포맷의 최종 보장은 에디터가 아니라 `format:check` 스크립트다 — 어떤 환경에서 작업하든 결과가 같아야 한다.

### 세지 않고 판단하지 않기

도메인 간 참조를 처음 `grep`으로 셌을 때 **22건**이 나왔다. 문자열 `champions/`를 포함한 모든 줄(주석·경로 언급 포함)을 센 결과였다. import 구문만 추리니 **4건**으로, ADR 기록과 정확히 일치했다.

"기록보다 늘었다"는 잘못된 전제로 작업 범위를 부풀릴 뻔했다.
