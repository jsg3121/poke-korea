# 주석 정리 (Phase 2-6)

> **작업 날짜**: 2026-09-27
> **브랜치**: `feature/1.61.0-comments`

## 📋 작업 개요

**작업 유형**: 리팩토링 (주석) + 하네스 보강
**담당**: jsg3121, claude

[컨벤션 개편](/convention-overhaul)이 남긴 마지막 항목이다. [ADR 후속 정리](/adr-followup)에 이은 Phase 2의 여섯 번째이자 마지막 작업.

## 🎯 작업 목표

**읽히지 않는 주석을 걷어낸다.**

작은 컴포넌트 하나에 10~20줄짜리 설명 블록이 붙어 있었다. 분량이 많아 정작 읽히지 않고, 코드를 찾는 데 방해가 됐다.

<!-- truncate -->

## 📉 왜 필요했나

`src/` 주석은 **4,383줄**이었다. 코드 29,376줄 대비 16.5%다.

| 항목                     | 수치                    |
| ------------------------ | ----------------------- |
| 블록 주석                | 1,345개 / 4,945줄       |
| 11줄 이상 블록           | **168개**               |
| 주석 비율 40% 이상 파일  | 24개                    |

극단적인 사례가 있었다. `chip.types.ts`는 **코드 1줄에 주석 7줄**, `adSense.ts`는 코드 47줄에 주석 120줄이었다.

### 문제는 분량만이 아니었다

타입 상세 페이지의 24줄짜리 블록을 보자.

```tsx
/**
 * 타입별 상성 상세 페이지(`/type-effectiveness/[type]`) — 18개 타입.
 *
 * ## 이 페이지가 존재하는 이유
 *
 * `독타입 약점`·`물타입 상성` 같은 타입별 롱테일 검색어에서 노출이 75.6% 빠졌고
 * (spec §26.8.2), 메인 계산기 한 장으로는 그 검색 의도를 되받을 수 없다.
 * ...
 */
```

여기엔 세 가지 문제가 겹쳐 있다.

- **문서 번호 참조**(`spec §26.8.2`) — `comments.md`가 명시적으로 금지한다. 문서가 이동·폐기되면 끊긴 링크가 된다
- **실측 수치**(75.6%) — 시간이 지나면 틀려진다
- **설계 배경 서술** — 같은 문서가 "설계 근거는 ADR·SPEC·changelog가 담당한다"고 규정한 영역이다

즉 규칙은 이미 있었고, 코드가 그 규칙과 어긋나 있었다.

## ✨ 주요 변경사항

### 변경 1: 남기는 기준을 둘로 좁혔다

처음엔 "외부 제약은 남긴다"로 시작했다. 그렇게 골라낸 26줄을 다시 보니 대부분 이미 문서에 있었다.

| 남겼던 항목             | 실제 기록 위치                   |
| ----------------------- | -------------------------------- |
| WCAG 터치 타겟          | UX-006·008·009, RES-003          |
| 동작 줄이기(SC 2.3.3)   | ADR-0015, changelog 1.56.0       |
| overflow 강제 계산      | ADR-0003, UX-010                 |
| useLayoutEffect SSR     | ADR-0015, changelog 1.56.0       |
| radio change 미발생     | changelog 1.54.0                 |
| CLS Skeleton 규격       | changelog 1.54.0                 |

**전부 사본이었다.** 사본은 원본이 갱신돼도 따라가지 못한다.

기준을 다시 좁혔다.

1. **외부 서비스 운영 제약** — 위반 시 즉각적 손해가 생기는 것(AdSense 정책)
2. **공용 함수 JSDoc** — `modules`·`utils`·`hooks`, 요약 1줄 + `@param`/`@returns`

그 외는 전부 제거했다. **JSX 주석(`{/* */}`)은 예외 없이 전부** — 마크업 구조는 코드가 말한다.

### 변경 2: 디렉토리별 5단계로 진행

한 번에 338개 파일을 고치면 검증이 불가능하다. 단계마다 `tsc`·`lint`·라우트 응답을 확인했다.

| 단계 | 대상                           | 변경 전 | 변경 후 |
| ---- | ------------------------------ | ------- | ------- |
| 1    | `src/app/`                     | 464줄   | 0줄     |
| 2    | `src/components/`              | 1,536줄 | 6줄     |
| 3    | `src/containers/`              | 926줄   | 2줄     |
| 4    | `views`·`constants`·`context`  | 669줄   | 36줄    |
| 5    | `modules`·`utils`·`hooks`      | 788줄   | 118줄   |

`src/graphql/`(1,167줄)은 codegen 생성물이라 손대지 않았다.

### 변경 3: 광고 슬롯은 유형과 위치만 남겼다

`adSense.ts`는 슬롯 ID 상수 파일이라 성격이 다르다. ID만 보고는 어느 지면인지 알 수 없다.

```ts
/**
 * 타입 상성 상세(/type-effectiveness/[type]) — 18개 타입 라우트 공용.
 * 위치: 복합 타입 블록 뒤·고유 효과 앞.
 */
export const TYPE_DETAIL_SLOTS = {
  mobile: '4288859636', // 320×100 디스플레이
  desktop: '6177029135', // 인아티클
} as const
```

채움률·RPM 수치와 포맷 전환 이력은 뺐다. 측정값은 시간이 지나면 틀려지고, 판단 근거는 RES-004에 있다.

### 변경 4: 다시 쌓이지 않도록 훅을 둔다

정리만으로는 시간이 지나면 되돌아간다. 편집 시점에 검사한다.

| 단계 | 구성                                             | 역할                             |
| ---- | ------------------------------------------------ | -------------------------------- |
| 1    | `detect-new-comment.sh` (`command` + `if` 필터)  | 편집에 새 주석이 있는지만 본다   |
| 2    | `prompt` 훅 (Haiku)                              | `comments.md` 기준으로 판정      |

2단으로 나눈 이유는 비용이다. `prompt` 훅은 편집마다 LLM을 호출하는데, `src/` 편집 대부분은 주석을 건드리지 않는다. 1단계에서 걸러내면 호출 자체가 일어나지 않는다.

`continueOnBlock: true`로 뒀다 — 주석은 되돌리기 쉬운 변경이라 턴을 끊기보다 사유를 피드백하는 편이 낫다.

## ⚠️ 구현 시 고려한 점

### lint 지시문을 지웠다가 되돌렸다

작업 중 `eslint-disable` 4건이 함께 지워졌다. 주석 형태지만 **실제로 동작하는 지시문**이라 제거 대상이 아니다.

lint가 새 경고(`exhaustive-deps` spread element)를 띄워 발견했고, 앞 단계에서 제거된 3건도 함께 복원했다. 훅 1단계에도 `eslint-disable`·`@ts-expect-error`·`prettier-ignore` 제외 규칙을 넣었다.

자동 스크립트가 주석과 지시문을 구분하지 못한 것이 원인이다. **검증이 없었다면 조용히 넘어갔을 변경이다.**

### 슬라이싱 대신 문자열 매칭

초반에 문자열 인덱스로 블록을 잘라내다가 `const`의 첫 글자를 날려 구문 오류를 냈다. `tsc`가 즉시 잡았다.

이후로는 정확한 문자열 매칭만 썼다. 대량 자동 편집에서는 "지울 범위를 계산"하는 방식보다 "지울 내용을 명시"하는 편이 안전하다.

### `comments.md`의 요약표가 실제 기준과 어긋나 있었다

정리를 마치고 보니 요약표에 "선택 이유·기각 사유 → JSDoc `@remarks`"로 적혀 있었다. 같은 문서의 "설계 근거는 ADR이 담당한다"는 원칙과 충돌한다.

훅 프롬프트가 이 문서를 기준으로 삼으므로, 어긋난 채 두면 훅이 잘못 판정한다. 실제 기준에 맞춰 함께 고쳤다.
