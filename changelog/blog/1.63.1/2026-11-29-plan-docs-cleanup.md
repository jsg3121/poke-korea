# 진행 상황을 계획 문서에서 GitHub Issues·PR·changelog로 이관

> **작업 날짜**: 2026-11-29
> **브랜치**: `feature/1.63.1-plan-docs-cleanup`

## 📋 작업 개요

**작업 유형**: 문서 (하네스)
**담당**: Claude Code

## 🎯 작업 목표

- 기획서·계획서에서 진행 상황(`상태` 항목, 진행 체크박스)을 없앤다.
- 남은 작업은 GitHub Issues, 완료 기록은 PR·changelog로 확인하도록 지침을 바꾼다.
- 진행 상황을 갱신하기 위해 브랜치를 따로 만드는 일을 없앤다.

<!-- truncate -->

## 📉 왜 필요했나

"대기 중인 작업이 있는가"를 확인하는 과정에서, 챔피언스 프론트엔드 계획서가 "계획 — Phase 0부터 순차 진행" 상태에 미체크 항목 38개로 남아 있었다. 실제로는 리스트·티어·상세·대회 페이지가 모두 배포된 뒤였다. 기능 기획서(`champions-pikalytics-enhancement.md`)도 미체크 62개가 남아 있었다.

`specs/plans/` 문서 7개는 문서당 커밋이 1~2개뿐이고 대부분 폴더 이동 커밋이었다. 진행 상황이 사실상 한 번도 갱신되지 않은 셈이다. 원인은 두 가지였다.

- **이중 기록**: 무엇을 했는지는 PR·changelog·커밋에 이미 남는다. 문서 체크박스는 같은 내용을 손으로 다시 옮겨 적는 일이라 누락될 수밖에 없다.
- **갱신 비용**: 문서도 파일이라 `main`에서 고칠 수 없고, 체크박스 하나를 고치려 해도 브랜치를 만들어야 했다. 비용이 크니 갱신이 계속 밀렸다.

## ✨ 주요 변경사항

### 진행 상황의 원본: `specs/index.md`

"진행 상황은 문서에 두지 않는다" 절을 새로 만들고, 다른 문서는 이 절을 링크한다.

| 알고 싶은 것     | 보는 곳                                 |
| ---------------- | --------------------------------------- |
| 무엇을 했는가    | 머지된 PR, changelog, 커밋 이력         |
| 무엇이 남았는가  | GitHub Issues                           |
| 왜 그렇게 했는가 | 기능 기획서, `architecture.md`, PR 본문 |

- `plans/`는 2026-11-28까지 작성한 보관본으로 두고 새로 쓰지 않는다.
- 기존 문서에 남은 `상태`·체크박스는 작성 당시 값이므로 현재 진행 상황의 근거로 쓰지 않는다. 기존 문서 자체는 고치지 않았다.

### 이슈 등록 절차

1. 남은 작업·미결 항목이 생기면 Claude가 이슈 제목과 본문을 제안한다.
2. 사용자가 확인한 뒤에만 `gh issue create`로 등록한다. 등록하지 않기로 하면 어디에도 남기지 않는다.
3. 그 작업을 처리하는 PR의 "관련 이슈" 섹션에 `Closes #N`을 적는다.

`Closes #N` 키워드는 PR이 기본 브랜치(main)를 향할 때만 해석된다([GitHub Docs](https://docs.github.com/en/issues/tracking-your-work-with-issues/using-issues/linking-a-pull-request-to-an-issue)). 서브 PR은 `feature/{version}`을 향하므로, 릴리즈 PR에서 서브 PR들의 관련 이슈를 모아 다시 적도록 했다.

| `.claude/specs/index.md`                   | `plans/` 보관본 전환, 진행 상황 절·이슈 등록 절차 신설                                |

| `.claude/conventions/guides/workflow.md`   | 문서 작업 예시의 "실행 계획서"를 기획서로 교체, 진행 상황 갱신용 브랜치를 만들지 않음 |
| `.claude/agents/product-planner.md`        | 메타 블록 `상태` 항목·7단계 상태 표·상태 갱신 절차 제거, 체크박스 금지                |
| `.claude/skills/create-pr/SKILL.md`·템플릿 | PR 본문에 "관련 이슈" 섹션 추가, 릴리즈 PR에서 `Closes #N` 재기재                     |

## ⚠️ 구현 시 고려한 점

| 안                               | 판단 | 이유                                                                             |
| -------------------------------- | ---- | -------------------------------------------------------------------------------- |
| 진행 상황을 Issues·PR로 이관     | 채택 | 이슈는 파일이 아니라 브랜치 없이 열고 닫을 수 있고, 완료 기록은 이미 PR에 남는다 |
| 계획서를 작성 시점 기록으로 고정 | 기각 | 남은 작업 목록이 어디에도 남지 않아 코드 대조가 반복된다                         |
| 문서만 main 직접 수정 허용       | 기각 | main 보호 훅에 예외가 생기고, 진행 상황이 어긋나는 근본 문제는 그대로다          |
| 다음 기능 브랜치에서 함께 갱신   | 기각 | 잊기 쉬워 지금과 같은 누락이 반복된다                                            |

## 🔍 검증

- 다른 에이전트·스킬·가이드에 기획서 `상태`·체크박스 갱신을 요구하는 지시가 남아 있지 않은지 검색으로 확인했다.
- 보관되는 `mobile-redesign-plan.md`를 참조하는 `ui-publisher-ds-alignment.md`의 링크는 문서를 지우지 않으므로 그대로 유효하다.
- 이슈 등록·자동 종료 흐름은 실제 이슈로 아직 확인하지 않았다. 첫 이슈가 생기는 작업에서 릴리즈 PR 머지 후 이슈가 닫히는지 확인이 필요하다.

## 📌 참고 사항

- 기존 기획서에 남아 있던 미결 항목(챔피언스 상세의 능력치 계산기 연동, 대회 상세의 EV 표시 방식, VP 계산기)은 이슈로 옮기지 않았다. 같은 논의가 다시 나오면 새 절차를 따른다.
- `.github/PULL_REQUEST_TEMPLATE.md`는 원래 `create-pr` 템플릿과 내용이 달라("검토한 대안" 없음) 이번에도 맞추지 않았다.
