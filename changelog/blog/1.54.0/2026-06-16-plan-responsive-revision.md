# 1.54.0 — UI 개편 기획서 재작성: 4단계 전략

> **작업 일자**: 2026-06-16
> **작업 브랜치**: `feature/1.54.0-plan-responsive-revision`

## 📋 작업 개요

**작업 유형**: 기획서 전면 재작성 (전략 정제)
**담당**: jsg3121 + Claude

[ADR-0007](/blog/1-54-0-responsive-pivot)의 반응형 전환에 더해, **"모든 페이지 개편
완료 전까지 상용 배포하지 않는다"** 는 전제가 확정되면서 전략을 재정비했다. 이 전제는
스트랭글러 패턴(중간 배포 시 신구 공존 유지)의 필요성을 없애므로, 기획서를 전면
재작성해 **4단계 전략**으로 정리했다.

<!-- truncate -->

## 🔄 무엇이 바뀌었나

| 기존 | 재작성 |
| --- | --- |
| 기반 먼저 → 화면 점진 교체(스트랭글러) | 디자인 시스템 구축 → 페이지 단위 전면 재구성 → 구버전 제거 |
| 중간 배포 전제 (신구 공존 필수) | **전체 완료 후 한 번에 배포** (공존은 작업 편의일 뿐) |
| Phase 0 / Phase 1+ | 4단계 (DS구축 → 재디자인 → 재구성 → 구버전제거) |

## 🎯 4단계 전략

1. **디자인 시스템 구축 (Foundations)** — 토큰·반응형 규칙 정의. 컴포넌트는 만들지 않음(2단계에서 페이지와 함께)
2. **페이지 단위 재디자인 + 컴포넌트 규격화** — 재사용+variant 기준 충족 시만 DS 컴포넌트로 승격
3. **구버전 유지하며 신버전 재구성** — 기존 컴포넌트 둔 채 반응형 단일 뷰로 페이지 재작성
4. **페이지 완료 후 구 컴포넌트 제거** — 사용처 0건 확인 후 삭제

## 💡 핵심 근거

- **배포 전제가 전략을 결정**: 중간 배포가 없으면 "항상 배포 가능" 제약이 사라져, 페이지를 과감히 전면 재구성 가능
- **DS는 필요 기반으로 성장**: 컴포넌트를 진공 상태에서 완성하지 않고, 페이지를 그려보며 실제 필요한 것만 규격화 (승격 기준: 2곳+variant)
