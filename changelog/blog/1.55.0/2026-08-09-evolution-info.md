# 포켓몬 상세 — 진화 정보 확장

> **작업 날짜**: 2026-08-09
> **브랜치**: `feature/1.55.0-evolution`

## 📋 작업 개요

**작업 유형**: 신규 기능 / UX 개선 / GraphQL 연동
**담당**: jsg3121, claude

## 🎯 작업 목표

포켓몬 상세 페이지는 전체 검색 노출의 약 49%를 차지하지만 CTR은 사이트 평균의 1/3 수준으로, 노출 대비 전환이 낮은 저평가 자산이다. 상세 페이지에 고유 정보를 더해 콘텐츠 두께를 키우고 상성표 단일 페이지 의존을 완화하는 것이 상위 전략이며, 그 핵심 항목이 **진화 정보 확장**이다.

기존 진화 체인은 진화 대상 이미지·번호·이름만 나열해 "어떤 조건으로 진화하는지"를 보여주지 못했다. 이번 작업으로 진화 조건 문장, 폼별 진화 분기, 버전별 조건 차이까지 담은 **진화 정보 섹션**으로 확장한다.

## ✨ 주요 변경사항

### 변경 1: 진화 조건 문장 표시

각 진화 대상 카드에 백엔드가 제공하는 완성 조건 문장(`description`)을 함께 표시한다. 예: "레벨 16 이상으로 레벨 업", "불꽃의돌 사용", "낮 시간대에 친밀도를 높인 상태로 레벨 업". 진화 방식 라벨(레벨업·아이템 등)은 백엔드 `triggerLabel`을 그대로 쓴다.

### 변경 2: 폼별 진화 그룹 섹션

리전폼이 있는 포켓몬은 진화 루트가 폼마다 다르다. 백엔드가 진화 정보를 폼별 그룹(`evolutionChain.groups`)으로 내려주고, 프론트는 이를 폼 그룹 섹션(기본 / 알로라 / 가라르 / 히스이 …)으로 나눠 렌더한다.

- **나옹**: 기본(→페르시온) / 알로라(→알로라 페르시온) / 가라르(→나이킹) 3섹션
- **침바루**: 히스이 1섹션 (기본형은 진화하지 않음)
- **미끄네일**: 기본 / 히스이 각각 3단계 계통(다단계 리전)

진화 대상의 이미지·이름·상세 링크는 각 진화 화살표(`edge`)의 폼 정보에서 가져와, 알로라 나인테일·황혼 루가루암처럼 폼별 대상도 정확히 표시·연결된다.

### 변경 3: 버전별 조건 분기 (버전 탭)

같은 진화가 게임 버전마다 조건이 다른 경우(리피아·글레이시아·우라오스 등), 버전 탭으로 전환해 각 버전의 조건을 볼 수 있다. 기본 노출은 대표(공통/최신) 조건 1개이고 나머지 버전은 클릭으로 확인한다. 버전명은 백엔드 `baseVersionGroupName`을 사용해, DLC 버전(예: 갑옷섬)도 기반 버전명("소드·실드")으로 표기된다.

### 변경 4: 진화 대상 폼별 상세 이동

진화 대상 카드를 누르면 그 대상의 **폼 상세**로 정확히 이동한다. 리전폼은 `/detail/{번호}/region`, 폼체인지는 `/detail/{번호}/form/{index}` 경로로 조립한다(백엔드 `resultFormType`/`resultFormIndex` 활용). 진화 전 카드도 현재 보고 있는 폼에 맞춰 이동한다.

### 데이터 연동

- 백엔드가 진화 정보를 폼별 `groups`로 재구축(리전폼만 그룹 분리, 기본형·노말폼은 BASE 그룹에 흡수).
- 각 `edge`에 진화 전/후 폼 정보(이름·이미지·폼 타입·index)가 완비돼, 프론트는 폼 필터링 없이 그룹을 그대로 섹션 렌더한다.

## 📌 참고 사항

- **진화 방식 라벨·버전명은 전부 백엔드 값 사용**: 프론트에 하드코딩된 매핑을 두지 않아, 신규 버전·DLC가 추가돼도 프론트 수정 없이 반영된다.
- **후속 작업**: 상세 페이지 정보 확장의 남은 항목(습득법 확장, 버전별 도감 설명, 기본 제원 등)은 진화 작업 분량이 커짐에 따라 1.56.0으로 이관한다. 상세 계획은 `.claude/specs/detail-page-expansion-spec.md` 참조.
