# 습득법 탭 4종 고정 + 알 기술·기술 가르침 404 수정

> **작업 날짜**: 2026-08-15
> **브랜치**: `feature/1.56.0-skills-expansion`

## 📋 작업 개요

**작업 유형**: 버그 수정 / UX 개선
**담당**: jsg3121, claude

## 🎯 작업 목표

직전 작업([습득 기술 통합 조회](./learnset-unified-query))에서 알 기술·기술 가르침 탭이 화면에 나타났으나, 두 가지 문제가 남아 있었다.

1. **탭을 누르면 404** — 탭이 링크하는 URL을 받을 라우트 파일이 없었다
2. **탭이 버전마다 나타났다 사라짐** — 데이터가 있을 때만 탭을 그리는 구조였다

## ✨ 주요 변경사항

### 변경 1: 404 수정 — `[method]` 동적 라우트 추가

`buildMovesPath`는 `/moves/egg`·`/moves/tutor` URL을 **생성했지만, 그 경로를 받을 라우트 파일이 `machine/page.tsx` 하나뿐**이었다. 습득법 라우팅을 enum 기반으로 전환할 때 파서·빌더만 바꾸고 라우트 파일 생성을 누락한 것이 원인이다.

습득법마다 파일을 만드는 대신 동적 세그먼트로 통합했다.

**변경 전**

```text
moves/machine/page.tsx                          ← machine만 존재
moves/version/[versionGroupId]/machine/page.tsx
```

**변경 후**

```text
moves/[method]/page.tsx                          ← machine·egg·tutor 전부
moves/version/[versionGroupId]/[method]/page.tsx
```

기존 `/moves/machine` URL은 동적 라우트가 그대로 받으므로 **색인된 경로가 유지된다.**

> **폼·리전 라우트 잠식 여부:** `[method]`가 같은 층의 `form`·`region`을 가릴 수 있어 확인이 필요했다. Next.js는 정적 세그먼트를 동적 세그먼트보다 우선 매칭하므로 문제가 없으며, 라우트 매칭 검증(아래)으로 실측했다.

### 변경 2: 탭 4종 항상 노출

기존엔 백엔드 응답(`skillsByMethod`)에 있는 습득법만 탭으로 그렸다. 그 결과 같은 포켓몬이라도 버전을 바꾸면 탭 개수가 달라졌다.

| 리자몽 | 변경 전 | 변경 후 |
| --- | --- | --- |
| 울트라썬·울트라문 | 레벨업 · 기술머신 · 기술 가르침 | 레벨업 · 기술머신 · 알 기술 · 기술 가르침 |
| LEGENDS Z-A | 레벨업 · 기술머신 | 레벨업 · 기술머신 · 알 기술 · 기술 가르침 |

> **Why 항상 노출인가:** 버전을 바꿨을 뿐인데 탭이 사라지면 사용자가 조작 실수로 오인한다. 레벨업·기술머신이 데이터 유무와 무관하게 늘 자리를 지키는 것처럼, 알 기술·기술 가르침도 동일하게 취급하는 편이 예측 가능하다. 데이터가 없는 탭은 들어갔을 때 "해당 버전에서 알 기술로 배우는 기술이 없습니다" 안내를 보여준다.

### 변경 3: 노출 습득법을 4종으로 한정

백엔드는 `isExposed=true`인 9종을 내려주지만, 전부 탭으로 만들면 모든 포켓몬 화면에 빈 탭이 늘어선다.

| 습득법 | 적재량 | 노출 |
| --- | ---: | --- |
| 레벨업 | 156,212 | ✅ |
| 기술머신 | 358,022 | ✅ |
| 알 기술 | 34,167 | ✅ |
| 기술 가르침 | 48,053 | ✅ |
| 폼체인지 | 59 | ❌ |
| 지가르데 큐브 | 40 | ❌ |
| 전기구슬 유전 | 10 | ❌ |
| 기술 떠올리기 | 1 | ❌ |

제외한 4종은 극소수 포켓몬에만 해당해, 노출 대비 화면 비용이 크다. 노출 목록은 `VISIBLE_LEARN_METHODS` 상수 한 곳에서 관리하므로 정책 변경 시 그 배열만 고치면 된다.

### 변경 4: 빈 탭 라벨 처리

데이터가 없으면 응답에 그룹 자체가 오지 않아 `methodLabel`을 얻을 수 없다. 탭을 항상 노출하는 이상 빈 탭에서도 "무엇이 없는지"를 말해야 하므로, 라벨을 마스터 쿼리(`useLearnMethodLabels`)에서 받도록 바꿨다.

## 🔧 기술적 세부사항

**신규 파일**

- `moves/[method]/page.tsx`
- `moves/version/[versionGroupId]/[method]/page.tsx`

**삭제 파일**

- `moves/machine/page.tsx` · `moves/version/[versionGroupId]/machine/page.tsx` (동적 라우트가 대체)

**함께 수정한 것**

삭제된 `machine/page.tsx`는 fetch에 `learnMethod`를 넘기지 않아, 기술머신 탭에서도 전 습득법을 받고 있었다. 신규 라우트는 슬러그에서 해석한 습득법을 그대로 쓴다.

**라우트 매칭 검증**

라우트 구조를 바꾸면 404나 오매칭이 나기 쉬워, 컴파일된 모듈로 실측했다.

- 탭 링크 8종(4습득법 × 버전 유무) → 전부 올바른 라우트에 매칭
- 폼·리전 4종 → `[method]`에 가려지지 않음 확인
- 슬러그 해석 7종 → 미노출 습득법(`reminder`·`form-change`)과 오타는 `undefined` (404 처리)

## 📌 참고 사항

- `src/graphql/`은 자동 생성 디렉토리(gitignore)이므로, 이 브랜치를 받은 뒤 백엔드 서버(`localhost:4000`)를 띄우고 `npm run codegen`을 실행해야 한다.
- 검증: `tsc --noEmit` 에러 0 / `npm run lint` 신규 경고 0 / `npm run build` 성공 / 라우트 매칭 19케이스 통과
- 미노출 습득법 URL(`/moves/reminder` 등)은 의도적으로 404다. 노출이 필요해지면 `VISIBLE_LEARN_METHODS`와 `METHOD_SLUG`에 추가하면 라우트가 따라온다.
