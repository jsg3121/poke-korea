# 기술별 포켓몬 목록 중복 — 백엔드 수정 확인 및 방어 로직 유지

## ✨ 백엔드 수정 확인

### 원인

`pokemon_learnsets`가 **습득법마다 1행** 구조라, 습득법이 2개 이상인 개체가 조립 단계에서 그 수만큼 중복 생성됐다. `methods` 배열은 이미 병합돼 있어 중복 노드의 필드가 전부 동일했던 것도 이 때문이다.

프론트에서 관찰했던 현상과 정확히 일치한다.

### 실측 결과

| 항목 | 수정 전 | 수정 후 |
| --- | ---: | ---: |
| 불꽃펀치 중복 | 13건 | **0건** |
| 칼춤 중복 | 14건 | **0건** |
| 불꽃펀치 `totalCount` | 187 | **163** |
| 칼춤 `totalCount` | 320 | **268** |

`totalCount`도 중복을 포함한 값이었고 함께 정상화됐다.

**페이지네이션 실동작**도 확인했다. 30건씩 4페이지를 순차 요청한 결과 누적 120건 전부 고유, 페이지 경계 겹침 0건이다.

### 덤으로 고쳐진 커서 버그

무효 커서로 다음 페이지를 요청하면 **1페이지가 돌아와** 무한 스크롤이 루프에 빠질 수 있었다. 이제 빈 `edges`를 반환한다.

```text
무효 커서 → edges 0건, hasNextPage=false
```

프론트가 발견하지 못한 문제였다.

## ✨ 프론트 방어 — 유지

원인이 사라졌지만 `dedupeEdges`와 `extractNodesFromEdges`의 중복 제거를 **유지한다.**

> **Why 유지인가:**
>
> - Relay connection에서 같은 cursor·id가 두 번 오는 것은 **어느 쿼리에서든 비정상**이므로, 걸러내도 정상 동작을 해치지 않는다
> - 비용이 사실상 없다 — `Set` 하나에 순회 한 번이고, 목록은 어차피 매번 순회한다
> - 중복이 렌더되면 React key 충돌 경고 + 목록 개수 불일치로 증상이 조용하지 않다. 한 번 겪은 지점이라 방어를 남긴다

### 주석 정정

문제는 주석이 **"V2가 중복을 내려준다"는 현재형**으로 쓰여 있던 것이다. 이제 사실이 아니므로 다음과 같이 바꿨다.

- 첫 줄에 **"현재 중복을 내려주는 쿼리는 없다"**를 명시
- 과거 사례는 "도입 배경(2026-08, 해소됨)"으로 시점을 붙여 기록
- 원인(`pokemon_learnsets` 1행 구조)과 해소 결과(`totalCount` 187 → 163)를 함께 남김
- 유지 근거 3가지를 명시해, 나중에 "왜 이게 있지?"에 답이 되도록 함

`extractNodesFromEdges` 쪽 주석도 정정했다 — 캐시 병합과 **별개로 필요한 이유**(SSR 초기 목록은 페이지가 `edges`를 직접 map해 캐시 정책을 거치지 않는다)를 명확히 적었다.

## 📊 변경 요약

| 항목 | 변경 |
| --- | --- |
| 중복 제거 로직 | 유지 (동작 변경 없음) |
| `dedupeEdges` 주석 | 현재형 → 해소 사실 + 유지 근거 |
| `extractNodesFromEdges` 주석 | 중복 방어가 두 곳에 필요한 이유 명시 |
| `merge` 내부 주석 | "중복이 올 수 있어" → 과거 사례 참조 |
