# 도감 검색창 입력 시 라벨이 헤더 밖으로 잘리는 문제 수정

> **작업 날짜**: 2026-10-01
> **브랜치**: `feature/1.61.1-main-search-label`

## 📋 작업 개요

**작업 유형**: 버그 수정
**담당**: Claude Code

## 🎯 작업 목표

데스크톱 도감(`/list`) 검색창에 입력할 때 "포켓몬 검색" 라벨이 잘리지 않게 하고, 라벨이 비켜나며 입력값이 가운데로 올라오는 모션은 유지한다.

<!-- truncate -->

## 📉 왜 필요했나

값이 생기면 라벨이 `top-[-1.25rem]`으로 이동해 검색창 바깥 위쪽, 즉 헤더 배경 위에 흰 글씨로 나타났다. 이 방식은 헤더 위쪽 여백이 `pt-6`(1.5rem)일 때를 전제로 만든 것이다.

2026-04-21 헤더 크기 축소(`31344de5`, 1.37.2)로 여백이 `pt-3`(0.75rem)으로 줄었다. 라벨은 1.25rem 위로 올라가는데 남은 공간이 0.75rem뿐이라, 넘치는 부분이 화면 맨 위(`fixed top-0`) 밖으로 나가 잘렸다.

## ✨ 주요 변경사항

### 라벨이 검색창 밖으로 나가지 않고 제자리에서 사라지게

**변경 전**:

```tsx
<p className={`... absolute top-2 ... transition-[top] duration-200 z-10
  ${hasValue && 'text-white top-[-1.25rem]'}`}>
```

**변경 후**:

```tsx
<p className={`... absolute top-2 ... transition-[opacity,transform] duration-200 z-10 pointer-events-none
  ${hasValue ? 'opacity-0 -translate-y-1' : 'opacity-100'}`}>
```

값이 생기면 라벨이 살짝 위로 움직이며 투명해진다. 입력값이 `top-[1.125rem]`에서 `top-[0.6rem]`으로 올라오는 기존 모션은 그대로다. 라벨이 검색창 안에서만 움직이므로 헤더 높이와 상관없이 잘리지 않는다.

`pointer-events-none`을 추가해, 라벨이 보이는 동안 라벨 영역을 눌러도 입력창이 클릭을 받도록 했다.

### 동작하지 않던 클래스 정리

- 래퍼의 `[&>.input__label]`, `[&>.wrapper__input]` 선택자를 지웠다. 해당 클래스를 가진 자식이 없어 아무 효과가 없었다.
- `${hasValue && '...'}`는 값이 없을 때 className에 `"false"` 문자열을 넣었다. 삼항 연산자로 바꿨다.

## ⚠️ 구현 시 고려한 점

| 방안 | 판단 |
| --- | --- |
| **검색창 안에서 사라지게 (채택)** | 모션이 남고 헤더 레이아웃과 상관없다. 파일 하나만 바뀐다. |
| 라벨을 검색창 안 위쪽에 고정 | 입력 중에도 라벨이 보이지만 디자인이 바뀌고, 3rem 높이에 라벨과 입력값을 함께 넣기 빠듯하다. |
| 헤더 위쪽 여백을 `pt-6`으로 복원 | 1.37.2의 헤더 축소를 되돌리는 셈이고, `top-28` 등 sticky 오프셋을 쓰는 여러 곳에 영향이 간다. |

## 🔍 검증

- `eslint`, `prettier --check`, `tsc --noEmit` 통과
- 실제 화면 동작은 확인하지 않았다.

## 📌 참고 사항

- 입력 중에는 "포켓몬 검색" 라벨이 보이지 않는다. 입력창의 접근 가능한 이름은 이번 변경과 상관없이 원래부터 `<label>`로 연결돼 있지 않았다.
