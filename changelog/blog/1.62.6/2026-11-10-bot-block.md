# SEO와 무관한 크롤러 4종을 robots.txt와 CloudFront Function으로 차단

> **작업 날짜**: 2026-11-10
> **브랜치**: `feature/1.62.6-bot-block`

## 📋 작업 개요

**작업 유형**: 성능 개선 (패치)
**담당**: jsg3121, Claude

## 🎯 작업 목표

검색 유입·광고·링크 미리보기와 관계없는 크롤러가 만들던 페이지 렌더와 API 호출을 없애, API 서버의 메모리 한도 재시작과 그로 인한 5xx를 줄인다.

<!-- truncate -->

## 📉 왜 필요했나

11월 4일부터 API 서버가 PM2 메모리 한도(300MB)에 걸려 하루 여러 번 재시작됐다. 재시작 중 요청이 실패해 ALB의 API 5xx는 하루 0건대에서 67~447건으로, ELB 502는 13~107건에서 94~412건으로 늘었다.

CloudFront 액세스 로그(11월 4일)를 보면 캐시를 통과해 오리진까지 간 문서 요청의 약 80%가 봇이었다. 모든 페이지가 요청마다 SSR을 실행하는 구조라, 문서 요청 1건이 API를 약 7.8회 호출한다.

| 봇                | 오리진 문서 요청 (하루) | 차단 여부          |
| ----------------- | ----------------------- | ------------------ |
| `meta-webindexer` | 7,154                   | 허용 유지          |
| `QlyzeBot`        | 6,668                   | 차단               |
| `SemrushBot`      | 4,638                   | 차단               |
| `Baiduspider`     | 3,175                   | 차단               |
| `ExaSearchBot`    | 2,083                   | 차단               |

`QlyzeBot`은 IP 하나로 한 시간에 6,668페이지를 요청했고, 그 시간대 API 요청이 평소의 약 3배로 튀었다.

결정 근거와 검토한 대안은 [ADR-0026](https://github.com/jsg3121/poke-korea/blob/main/.claude/decisions/records/ADR-0026-bot-blocking-at-edge.md)에 정리했다.

## ✨ 주요 변경사항

### 변경 1: robots.txt에 차단 그룹 추가

robots.txt를 지키는 크롤러는 요청 자체를 보내지 않으므로, 오리진 부하와 CloudFront 요청 과금이 함께 사라진다.

**변경 후** (`src/app/robots.ts`):

```ts
const SEO_UNRELATED_AGENTS = [
  'QlyzeBot',
  'SemrushBot',
  'Baiduspider',
  'ExaSearchBot',
]

// rules
{
  userAgent: SEO_UNRELATED_AGENTS,
  disallow: ['/'],
},
```

### 변경 2: CloudFront Function UA 차단 목록 확장 (저장소 밖)

robots.txt는 강제력이 없어, `poke-korea.com` 배포의 viewer-request 함수 `device-validator-ipblock`에도 같은 4종을 추가한다. 기존 Bytespider 차단과 같은 방식으로 `403` + `cache-control: no-store`를 반환한다.

```js
var BLOCKED_UA_TOKENS = ['bytespider', 'qlyzebot', 'semrushbot', 'baiduspider', 'exasearchbot']
```

이 함수는 AWS 콘솔에서 관리하므로 코드 배포와 별도로 게시해야 한다.

## 🔍 검증

- `prettier`·`eslint`·`tsc` 통과
- 변경한 `robots()` 결과를 Next.js의 robots.txt 생성 함수(`resolveRobots`)에 넣어 출력 확인. 새 그룹이 `Disallow: /`로 생성되고 기존 그룹은 그대로다
- 로컬 3000번 포트가 11월 3일 빌드의 프로덕션 서버여서 실제 `/robots.txt` 요청으로는 확인하지 못했다. 배포 후 운영 URL로 확인한다

## 📌 참고 사항

- `meta-webindexer`는 요청이 가장 많지만 Meta AI 검색용이라, AI 검색 크롤러를 허용하는 기존 정책에 맞춰 허용을 유지했다
- 차단 대상 봇은 이틀 동안 수백 개의 IP를 써서(Baiduspider 601개, ExaSearchBot 512개) IP가 아니라 UA로 차단했다
- 후속 관찰 대상: 대상 UA의 요청 수와 `403` 비율, ALB `api-connect`의 요청 수·5xx, API 서버의 메모리 한도 재시작 횟수
