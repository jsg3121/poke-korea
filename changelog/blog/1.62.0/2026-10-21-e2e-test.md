# E2E 테스트 도입 — Playwright 설정, 첫 spec, QA 검사 스킬

> **작업 날짜**: 2026-10-21
> **브랜치**: `feature/1.62.0-list-search`

## 📋 작업 개요

**작업 유형**: 기능 추가(테스트 환경) / 문서
**담당**: jsg3121, claude

## 🎯 작업 목표

사용자 흐름(검색·필터 등)을 브라우저에서 자동으로 확인하는 E2E 테스트를 돌릴 수 있게 하고, QA 검사 흐름(`qa-orchestrator`, `/create-pr`)에서 E2E를 다른 검사와 같은 방식으로 실행·판정하게 한다.

<!-- truncate -->

## 📉 왜 필요했나

- `@playwright/test`는 설치돼 있었지만 설정 파일, 테스트, 실행 스크립트가 없었다. 화면 캡처 스크립트만 Playwright를 쓰고 있었다.
- `/create-pr`의 E2E 검증 옵션은 `npm run build && npx playwright test`를 실행하게 돼 있었지만, 돌릴 테스트가 없었다. 게다가 빌드 모드는 운영 API를 호출하고, 개발 서버가 떠 있으면 `.next`를 공유해 서버가 죽는다.
- 같은 브랜치의 목록 검색 작업에서 "첫 검색어가 사라짐", "초기화해도 입력창이 남음" 같은 흐름 버그를 손으로 재현하고 확인해야 했다. 다시 생기면 자동으로 잡을 방법이 없었다.

## ✨ 주요 변경사항

### 변경 1: Playwright 설정 (`playwright.config.ts`)

- **개발 서버 기준**: `baseURL`은 `localhost:3000`이고 `BASE` 환경변수로 바꿀 수 있다. `webServer`를 쓰지 않아 Playwright가 서버를 띄우지 않는다.
- **모바일·데스크톱 두 프로젝트**: 헤더·푸터를 화면 폭이 아니라 User-Agent로 나누므로(`app/layout.tsx`), 모바일은 iPhone UA + 375px, 데스크톱은 Mac Chrome UA + 1440px로 실행한다. 기존 캡처 스크립트와 같은 값이다.
- `npm run test:e2e` 스크립트, `test-results/`·`playwright-report/` gitignore.

### 변경 2: 첫 spec (`e2e/`)

| spec                         | 검증하는 흐름                                                                              |
| ---------------------------- | ------------------------------------------------------------------------------------------ |
| `list/search.spec.ts`        | 진입 시 검색어 유지, 첫 입력 반영과 입력창 유지, 공백 제거, 다 지우면 제거, 초기화 시 입력창 비움 |
| `list/filter-modal.spec.ts`  | 세대·포함 조건 제출, "모두" 선택 시 파라미터 제거, 다시 열면 상태 유지, 검색어·타입 파라미터 유지 |
| `moves/search.spec.ts`       | 입력 반영, 결과 없음 → "검색·필터 초기화" 시 입력창 비움                                      |
| `ability/search.spec.ts`     | 입력 반영, 다 지우면 제거                                                                  |

요소는 역할·이름(`getByRole`, `getByText`)으로 찾고, URL 반영은 `expect.poll`로 기다린다. 고정 시간 대기는 쓰지 않는다.

### 변경 3: 작성 지침 (`conventions/guides/testing.md`)

실행 조건(개발 서버, 빌드 금지 이유), 검증 대상과 대상이 아닌 것(화면 모양·정확한 데이터 값), 파일 위치(`e2e/{라우트}/{흐름}.spec.ts`), 선택자 우선순위, 대기 규칙, 디바이스 분기, 테스트 독립성, 버그를 고칠 때 "재현 테스트가 먼저 실패하는지 확인" 순서를 정했다.

### 변경 4: QA 검사 스킬 `e2e-check`와 연결

- **`skills/e2e-check/SKILL.md`**: 서버 응답 확인 → 변경 파일 기준 spec 선별(라우트·도메인 대응, 공용 코드는 사용처 추적, 애매하면 전체) → 실행 → 실패한 테스트만 한 번 재실행해 회귀(🔴)·불안정(🟡)·환경 문제(실행 불가)로 분류 → 테스트 부재 보고. 보고만 하고 코드·테스트를 고치지 않는다.
- **`qa-orchestrator`**: 검사 선별 표, 통합 등급(E2E 회귀 🔴, 불안정·테스트 부재 🟡), 판정에 추가했다. "실행 불가"는 통과로 치지 않고 `⚠️ 조건부 진행`으로 둔다.
- **`/create-pr`**: E2E 옵션이 빌드 없이 `e2e-check` 절차를 따르도록 바꿨다.
- CLAUDE.md 명령어 표와 문서 참조 표, `skills/index.md`, `conventions/index.md`, `structure.md`를 갱신했다.

## 🔍 검증

- `npm run test:e2e`: 24개 통과(spec 12개 × 모바일·데스크톱), 약 16초
- **테스트가 버그를 잡는지 확인**: `useSearchParamInput`에서 초기화 감지 줄(`setKeyword('')`)을 잠시 빼고 실행했다. 도감 목록·기술 목록의 초기화 테스트 4개가 "입력창이 비워졌는지" 검증에서 실패했고, 복구 후 다시 전부 통과했다.
- `tsc --noEmit`, ESLint, Prettier: 통과

## ⚠️ 구현 시 고려한 점

- **빌드 대신 개발 서버에 붙인다.** 빌드 모드는 `buildMode.module.ts`에 따라 운영 API를 호출해 결과가 운영 데이터에 흔들리고 운영에 부하를 준다. 개발 서버는 사용자가 관리하므로 테스트와 검사 스킬 모두 서버를 띄우지 않고, 서버가 없으면 "실행 불가"로 알린다.
- **정확한 개수·값을 단정하지 않는다.** 로컬 DB 기준이라 데이터가 바뀌면 깨진다. 결과가 없는 상태는 존재하지 않는 검색어로 만든다.

## 📌 참고 사항

- 단위 테스트 도구(Vitest 등)는 이번에 넣지 않았다. 상세 능력치 탭의 계산 함수 작업 때 정한다.
- 모바일 도감 목록 검색 input에는 자체 접근 가능한 이름이 없어서, 감싸는 `role="search"` 영역의 이름으로 범위를 좁혀 찾는다. 접근성 측면에서 input에 라벨을 다는 개선 여지가 있다.
