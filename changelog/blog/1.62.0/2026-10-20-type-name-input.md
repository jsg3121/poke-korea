# 상성 계산기 포켓몬 이름 입력

> **작업 날짜**: 2026-10-20
> **브랜치**: `feature/1.62.0-type-name-input`

## 📋 작업 개요

**작업 유형**: 기능 추가
**담당**: jsg3121, claude

## 🎯 작업 목표

상대 포켓몬의 이름만 알면 타입 조합을 몰라도 약점을 바로 볼 수 있게 한다. 기본 종뿐 아니라 메가진화·리전폼·폼체인지도 각 폼의 실제 타입으로 계산한다.

<!-- truncate -->

## 📉 왜 필요했나

- 계산기는 타입 칩을 최대 2개 직접 고르는 방식이라, 상대의 타입 조합을 이미 알아야 쓸 수 있었다. 리전폼·메가처럼 기본 종과 타입이 다른 폼은 더 헷갈린다.
- 타입 상성은 랜딩 세션 2위(12,837, 28일)이고 "포켓몬 상성 계산기" 질의 1.2위·CTR 56.9%인 핵심 검색 자산이다. 재방문 PV 비중이 71.4%라 "빠른 조회"를 더 빠르고 정확하게 만드는 쪽이 효과가 크다고 봤다.
- 근거와 결정 과정은 기획서 `.claude/specs/features/type-calculator-name-input-spec.md`에 있다.

## ✨ 주요 변경사항

### 변경 1: 이름 입력과 자동완성

- 계산기 섹션의 가이드 문구 아래에 "포켓몬 이름으로 찾기" 입력을 두었다.
- 백엔드 `searchPokemonWithAllForms`로 검색한다(디바운스 500ms, `useQuery` + `skip`). 폼 이름·지역명으로도 찾고 어순과 무관하다("알로라 라이츄" → "라이츄 알로라의 모습").
- 자동완성은 썸네일·폼 이름·타입 태그 행을 개수 제한 없이 담고 패널 안에서 스크롤한다. 각 행은 버튼이라 Tab으로 이동하고 Enter·Space로 고른다.
- 로딩·0건·오류 상태를 각각 안내한다. 검색어는 30자로 제한하고 5단어를 넘으면 요청하지 않는다(백엔드 상한 초과 시 오류 대신 0건).

### 변경 2: 선택 후 동작

| 상황 | 동작 |
| --- | --- |
| 포켓몬을 고름 | 칩이 그 폼의 타입으로 바뀌고 나머지 칩은 비활성. 선택 표시줄(썸네일·이름·타입)이 나타나고 결과 제목으로 부드럽게 스크롤 |
| 켜진 칩을 누름 / 선택 초기화 | 이름 선택·칩·입력을 모두 비움 |
| 가이드 문구 | "`{폼 이름}` 기준으로 계산했어요. 다른 타입을 고르려면 선택 초기화를 눌러주세요." |

- 칩으로만 고를 때는 기존처럼 2개를 고르면 나머지가 비활성이다.
- 선택 초기화 버튼을 44px로 키웠다.
- 데스크톱은 선택 표시줄을 입력창 오른쪽, 같은 높이에 둔다.

### 변경 3: 상태와 데이터

- 전용 쿼리 `SearchPokemonFormsWithTypes`(`types`·`imagePath` 포함, `id` 제외 — 백엔드 `id`는 폼을 가리키는 고정값이 아니다).
- Context에 이름 선택 상태(`selectedPokemon`)와 타입 일괄 지정 액션을 추가하고, Context를 `null` 기본값 + `useTypeEffectiveness()` 훅으로 정리했다.

### 변경 4: GA4 이벤트

| 이벤트 | 시점 | 파라미터 |
| --- | --- | --- |
| `use_name_search` | 포켓몬을 고를 때마다 | `source`, `query`(20자), `pokemon_number`, `form_type`, `is_first_search` |
| `use_type_calc` | 이름 선택은 즉시, 칩은 1.5초 동안 그대로일 때(같은 조합은 페이지 로드당 1회) | `input_method`, `types` |

### 변경 5: 공용 컴포넌트

- `SearchInput`(DS): 글자 16px(`text-md` 토큰 신설, iOS 입력 확대 방지), 포커스 링을 진한 배경에서 보이는 색으로, ref·나머지 input 속성·`type` 전달. **기술·특성 검색 입력도 글자가 16px로 커지고 포커스 링이 보이게 된다.**
- 헤더 검색 결과 목록의 props 타입을 스키마 타입에서 쿼리 결과 타입으로 바꿨다. 스키마에 `types`가 추가되며 생긴 타입 오류를 해소한다.

## 🔍 검증

- `tsc --noEmit`, 변경 파일 ESLint·Prettier 통과
- dev 서버에서 `/type-effectiveness`·`/moves`·`/ability` 200 확인
- 브라우저에서 사용자가 직접 확인: 이름 검색·폼 검색, 칩 비활성·해제, 결과 스크롤, 데스크톱 정렬, 포커스 링 여백
- 운영 API에서 `types` 필드와 폼 이름·어순 검색이 이미 배포된 것을 확인(2026-10-20)
- **확인하지 않은 것**: GA4 실제 전송(개발 환경에 gtag 없음, 운영 배포 후 DebugView로 확인), iOS 실기기 입력 확대·키보드와 스크롤 겹침

## ⚠️ 구현 시 고려한 점

- 방향키 탐색(ARIA 콤보박스)은 넣지 않았다. WCAG 2.1.1은 키보드로 쓸 수 있으면 충족하고, 사이트의 다른 검색도 Tab 이동 방식이다.
- 패널은 입력 영역에 포커스가 있을 때만 보이게(CSS `group-focus-within`) 해 열림 상태를 따로 두지 않았다. 패널 mousedown을 막아 Safari에서 클릭이 사라지지 않게 했다.
- 입력창 옆 빈 공간에 광고를 넣는 안은 AdSense 게재 위치 정책(드롭다운 근처 실수 클릭, 요청하지 않은 요소 새로고침) 때문에 기각했다.

## 📌 참고 사항

- GA4 콘솔에서 맞춤 측정기준 등록이 필요하다: `source`, `query`, `pokemon_number`, `form_type`, `is_first_search`, `input_method`, `types`
- `/type-effectiveness` 메타데이터·H1은 바꾸지 않았다. 배포 후 2주는 효과 귀속을 위해 동결한다.
