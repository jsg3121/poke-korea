# 네이버 애널리틱스 제거, 사용자 지표를 GA4로 일원화

> **작업 날짜**: 2026-11-03
> **브랜치**: `feature/1.62.5-remove-naver-analytics`

## 📋 작업 개요

**작업 유형**: 성능 개선 / 운영 정리
**담당**: jsg3121, Claude

## 🎯 작업 목표

사용자·유입 지표의 기준을 GA4 하나로 정하고, 더 이상 쓰지 않는 네이버 애널리틱스 스크립트를 모든 페이지에서 제거한다.

<!-- truncate -->

## 📉 왜 필요했나

- **지표 기준이 둘로 나뉘어 있었다.** GA4와 네이버 애널리틱스는 집계 방식이 달라 같은 기간에도 수치가 어긋났고, 어느 쪽을 기준으로 판단할지 매번 헷갈렸다. 네이버 애널리틱스로 볼 수 있는 방문·인기 페이지 지표는 GA4에서도 볼 수 있고, GA4는 이벤트·사용자 지표를 더 넓게 제공하며 API로 조회할 수 있다.
- **모든 페이지에서 스크립트가 로드되고 있었다.** Lighthouse 모바일 측정(`/detail/25`) 기준으로 `wcslog.js`가 High 우선순위로 preload되었고, 관련 요청이 약 28KB(`naver.net` 10KB, `pstatic.net` 18KB), 메인 스레드 약 70ms였다. 광고·GTM에 비하면 작지만, 쓰지 않는 도구의 비용이다.

## ✨ 주요 변경사항

### 변경 1: 네이버 애널리틱스 스크립트 제거

`src/app/layout.tsx`에서 `wcslog.js` 로드 스크립트와 초기화 스크립트(`naver-analytics`, `naver-analytics-init`)를 제거했다.

`naver-site-verification` 메타 태그는 **유지**했다. 네이버 애널리틱스가 아니라 네이버 서치어드바이저(검색 등록) 소유 확인용이다.

### 변경 2: 개인정보처리방침 정리

수집 도구가 바뀌었으므로 `src/views/privacy/Privacy.view.tsx`에서 네이버 애널리틱스 관련 서술 세 곳을 삭제했다.

- 제3자 서비스 목록의 네이버 애널리틱스 항목
- 자동 수집 정보 목록의 "방문 통계 및 유입 경로 분석 데이터"
- 분석 쿠키 항목의 "네이버 애널리틱스"

### 변경 3: 분석 문서 기준 변경

`.claude/analyzer/index.md`의 네이버 애널리틱스 절을 "2026-11-03 수집 중단"으로 바꾸고, GA4를 유일한 기준으로 삼는다는 결정과 이유를 남겼다. 2026-11-03 이전 기간의 국내 유입을 교차 확인할 때만 과거 데이터를 참고한다.

## 🔍 검증

- 변경 파일 대상 `prettier`·`eslint` 확인 (생성 파일 미존재로 나는 `import/no-unresolved` 제외)
- `src/` 전체에서 `wcs`·네이버 애널리틱스 참조가 남지 않았는지 확인
- 배포 후 확인 필요: 페이지 HTML과 네트워크 요청에 `wcs.naver.net`이 나타나지 않는지

## 📌 참고 사항

- 네이버 애널리틱스 대시보드의 과거 데이터는 그대로 남는다. 계정 해지는 별도로 판단한다.
- 성능 효과는 같은 버전의 다른 작업과 함께 1.62.5 성능 측정 글에서 페이지별로 비교한다.
