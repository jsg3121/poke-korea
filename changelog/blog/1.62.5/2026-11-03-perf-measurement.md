# 1.62.5 성능 측정 — 배포 전 Lighthouse 모바일 기준값

> **작업 날짜**: 2026-11-03
> **브랜치**: `feature/1.62.5-perf-measurement`

## 📋 작업 개요

**작업 유형**: 성능 측정 (문서)
**담당**: jsg3121, Claude

## 🎯 작업 목표

1.62.5의 네 작업이 페이지별로 얼마나 효과가 있었는지 비교할 수 있도록, 배포 전 운영 사이트의 Lighthouse 모바일 수치를 기록한다. 배포 후 같은 방법으로 다시 측정해 이 글에 추가한다.

<!-- truncate -->

## 📉 왜 필요했나

1.62.5는 성격이 다른 네 작업을 한 번에 배포한다.

| 작업                    | 기대 효과                                               |
| ----------------------- | ------------------------------------------------------- |
| 네이버 애널리틱스 제거  | 서드파티 요청 약 28KB 감소                              |
| CSS 기본 로딩 복원      | 폰트 preload 제거 — LCP 이미지와의 대역폭 경쟁 해소     |
| 폰트 재서브셋           | 폰트 전송량 600KB → 200KB                               |
| IntentLink 전환         | 화면에 보인 링크의 RSC prefetch 제거 — CloudFront 요청 감소 |

Lighthouse 점수는 측정할 때마다 흔들린다. 배포 후 "좋아졌다"를 판단하려면 같은 조건에서 잰 기준값이 먼저 있어야 한다.

## 🔍 측정 방법

| 항목      | 내용                                                                                                        |
| --------- | ----------------------------------------------------------------------------------------------------------- |
| 도구      | Lighthouse 12.6.1, 모바일(`--form-factor=mobile`, 기본 시뮬레이션 스로틀링), 성능 카테고리만               |
| 대상      | 운영 사이트 13개 대표 페이지 (캐시 우회 쿼리 없이 실제 주소)                                                |
| 횟수      | 페이지마다 CloudFront 캐시를 1회 예열한 뒤 5회 측정, **중앙값** 기록                                        |
| 측정 시각 | 2026-11-03 07:5x~08:1x UTC (1.62.4 배포 직후, 1.62.5 배포 전)                                               |
| 환경      | 클라우드 작업 환경의 헤드리스 Chromium (미국 리전, 프록시 경유)                                             |
| 스크립트  | `.claude/analyzer/scripts/lighthouse-batch.sh`, `lighthouse-summary.py`                                    |

배포 후에도 **같은 스크립트, 같은 환경**으로 측정해야 비교할 수 있다. 측정 중에는 빌드처럼 CPU를 많이 쓰는 작업을 돌리지 않는다.

## 📌 참고 사항

### 느린 측정(FCP 6초대)의 원인은 광고 스크립트 타이밍으로 보인다

느린 회차와 빠른 회차를 비교하니, 느린 회차에서는 CSS와 폰트가 0.5초 안에 다 내려왔는데도 첫 그리기가 약 2.5초(관측값)에야 일어났다. 그 직전에 AdSense 관련 스크립트(`adtrafficquality.google/sodar` 등)가 로드되고 있었다. HTML이 빨리 도착한 회차에서 광고 초기화가 첫 그리기보다 먼저 실행된 경우로 보인다.

이 현상은 1.62.5 작업과 별개다. 배포 후 비교에서는 중앙값과 함께 **느린 측정 비율이 바뀌었는지**도 따로 본다. 광고 스크립트 로딩 시점 조정은 별도 개선 후보다.

### 측정 결과에 포함되지 않는 효과

- **IntentLink 전환**은 페이지 로딩이 아니라 페이지 안에서 링크를 볼 때 생기는 요청을 줄인다. Lighthouse 수치보다 **CloudFront `Requests` 지표**(`E3TRB0VXGC6JWI`)와 액세스 로그의 RSC 비중(배포 전 7일 기준 전체 요청의 69.7%)으로 비교한다.
- 이 환경은 미국 리전이라 한국 사용자의 실제 체감과 다를 수 있다. 실사용 지표는 Search Console Core Web Vitals로 따로 확인한다.
