# 포켓몬 기본 제원 공개

> **작업 날짜**: 2026-08-26
> **브랜치**: `feature/1.58.0-base-spec`

## 📋 작업 개요

**작업 유형**: 기능 추가
**담당**: jsg3121, claude

## 🎯 작업 목표

상세 페이지에 그동안 없던 기본 제원을 노출한다. 상성표 한 페이지에 쏠린 유입 의존을 낮추기 위해, 이미 검색 노출을 많이 받는 상세 페이지의 콘텐츠를 두껍게 만드는 작업의 연장이다.

<!-- truncate -->

## 📉 왜 추가했나

Search Console 실측상 상세 페이지는 **전체 검색 노출의 49%(88만 회)** 를 받는데 CTR은 사이트 평균의 약 1/3(1.20%)에 그친다. 구글은 이미 상세 페이지를 대량으로 노출시키는데 콘텐츠가 얇아 클릭으로 이어지지 않는 상태다.

새 페이지를 만들어 새 랭킹을 얻는 장기전이 아니라 **이미 랭크된 페이지의 전환율을 올리는** 작업이라 유입 ROI가 확실하다. 기본 제원은 그중 공수가 가장 낮은 항목이었다.

## ✅ 추가된 항목

카드 2장으로 나눠 넣었다. 기존 "기본 정보"(이름·도감번호·세대·타입)는 검색·식별용 메타라 성격이 달라 그대로 두고, 생태·수치 정보를 분리했다.

### 신체 정보

| 항목 | 예시(이상해꽃) |
| --- | --- |
| 분류 | 씨앗포켓몬 |
| 키 | 2.0m |
| 몸무게 | 100.0kg |

전설·환상 포켓몬은 카드 제목 옆에 배지가 붙는다. 해당하지 않는 종은 배지를 렌더하지 않는다 — 1,025종 중 대부분이 해당 없음이라 "아니오" 행을 만드는 건 의미가 없다.

### 육성·포획 정보

| 항목 | 예시(이상해꽃) |
| --- | --- |
| 포획률 | 45 / 255 (게이지) |
| 기초 친밀도 | 70 |
| 성비 | 수컷 87.5% / 암컷 12.5% (막대) |
| 알 그룹 | 괴수, 식물 |
| 부화 카운트 | 20 |
| Lv.100 총 경험치 | 1,059,860 |

## 🔀 폼별로 다른 키·몸무게

키와 몸무게는 폼마다 값이 다르다. 폼을 전환하면 해당 폼의 값이 나온다.

| 폼 | 키 / 몸무게 |
| --- | --- |
| 이상해꽃(원종) | 2.0m / 100.0kg |
| 메가이상해꽃 | 2.4m / 155.5kg |
| 거다이맥스 이상해꽃 | 24.0m / 1000.0kg |

호바귀·펌킨인처럼 소과종~특대과종으로 나뉘는 노말폼도 각각의 크기를 보여준다(펌킨인 소과종 0.7m / 9.5kg).

스탯이 이미 쓰던 활성 폼 선택 로직(`getActiveFormInfo`)에 제원을 얹어, 폼 전환 기준을 한 곳에서 관리하도록 했다.

## 🧩 표기를 정할 때 걸렀던 것들

원시값을 그대로 두면 의미를 알기 어려운 항목이 있어 표기 방식을 따로 정했다. 이 과정에서 **근거가 없어 뺀 것**이 몇 가지 있다.

### 포획률 등급("어려움") — 뺐다

`45`에 "(어려움)" 같은 등급을 붙이는 안을 검토했으나 폐기했다. 게임 데이터에 있는 건 0~255 정수뿐이고 이를 등급으로 나누는 **공식 기준이 없다.** 등급 경계를 우리가 정하면 근거 없는 자체 분류가 검색에 색인된다.

### 포획 확률(%) — 뺐다

`45 / 255`를 백분율로 바꿔 "약 11.94%"를 병기하는 안도 검토했다. 실제 포켓몬 포획 공식으로 계산하면 이 값이 맞지만, **게이지 채움 비율(45/255 = 17.6%)과 어긋난다.** 사용자는 막대를 보고 17~18%로 읽는데 숫자는 11.94%라 오해를 부른다. 피카츄는 격차가 더 크다(막대 74.5% vs 확률 35.18%).

`captureRate`는 확률이 아니라 포획 계산식의 **계수**다. 실제 확률은 체력·볼 종류·상태이상에 따라 달라진다. `45 / 255`는 "255 만점 중 45"라는 척도상 위치를 정확히 표현하고 게이지도 같은 것을 그리므로, 이 조합만 남겼다.

### 준전설 배지 — 못 넣었다

전설/준전설/환상 3종으로 나누는 안을 검토했으나 불가능했다. DB에는 `isLegendary`·`isMythical` 두 개의 boolean만 있고, 준전설로 통칭되는 종(프리져·라이코·레지락·토네로스 등)이 전부 `isLegendary: true`에 묶여 있다. 애초에 준전설은 팬 커뮤니티 분류라 PokéAPI·공식 게임 데이터에 존재하지 않는다.

### 부화 걸음수 환산 — 뺐다

`(카운트+1)×사이클`로 걸음수를 환산해 병기하는 안을 검토했으나 폐기했다. 이 환산식은 공식 문서가 아니라 **커뮤니티 역공학 결과**이고, 사이클이 세대마다 다르다.

| 세대 | 사이클당 걸음수 |
| --- | ---: |
| 2~4세대 | 255 |
| 5~7세대 | 257 |
| 8세대 이후 | 128 |

여기에 불꽃몸통·마그마의무기 특성이 있으면 다시 절반이 된다. 이 사이트는 8세대 이후가 주 대상이라 흔히 알려진 255 기준을 쓰면 최신작과 맞지 않는다. 조건부 근사치를 주 표기로 올리는 건 위 두 항목을 뺀 기준과 어긋나므로 **카운트 원시값만** 노출한다.

## 🎬 게이지 진입 모션

포획률·성비 게이지가 뷰포트에 들어오면 0에서 채워진다. 능력치 막대와 같은 방식이다.

구현하면서 보니 이 로직이 `StatBar`와 `ChampionsMetaList`에 **똑같이 복제돼 있었다.** 세 번째 사본을 만드는 대신 `useEnterViewProgress` 훅으로 추출하고 기존 두 곳도 교체했다. 두 파일에서 137줄이 빠지고 13줄로 대체됐다.

훅이 지키는 것은 셋이다.

- **SSR HTML에는 처음부터 최종값이 렌더된다.** 진행도 초기값이 `1`이고, 모션이 가능할 때만 클라이언트에서 0으로 되감는다. 검색 크롤러와 JS 비활성 환경에서 게이지가 0으로 보이지 않는다.
- **`prefers-reduced-motion` 사용자는 모션 없이 최종값을 본다.** IntersectionObserver 미지원 환경도 같다.
- **이미 화면에 보이는 상태로 시작하면 모션을 생략한다.** 최초 관찰 콜백은 "관찰 시작 시점의 상태"라, 여기서 되감으면 최종값 → 0 → 카운트업의 이중 표시가 되어 어색하다.

`ChampionsMetaList`의 진입 임계값(0.25)은 `StatBar`(0.35)와 달라 훅 옵션으로 그대로 유지했다.

## ♿ 접근성

- 게이지·막대는 **보조 시각화**다. 실제 정보는 형제 텍스트가 전달하고 막대에는 `aria-hidden`을 줬다(스탯 카드 `StatBar`와 동일 원칙). 스크린리더가 수치를 중복해 읽거나 막대만 남아 정보가 유실되는 것을 막는다.
- 성비는 색상만으로 암수를 구분하지 않는다(WCAG 1.4.1). "수컷"·"암컷" 텍스트를 항상 병기하고, 막대 경계에 구분선을 둬 색 인지가 어려워도 분할 지점이 형태로 드러나게 했다.
- 값이 없는 항목은 `dd`를 비우지 않고 **"불명"** 으로 명시한다. 빈 값으로 두면 "원래 없는 것"인지 "로딩 실패"인지 구분되지 않는다.
- 카드는 `<section aria-labelledby>` + `<dl>/<dt>/<dd>` 구조로, 기존 기본 정보 카드와 같은 패턴을 따른다.

> **폼 값 폴백은 `??`를 쓰지 않는다.** 폼의 `height`/`weight`가 `null`일 때 `?? 원종값`으로 폴백하면, 값이 **공식적으로 불명인 폼**에 원종 수치가 잘못 표시된다. 실제로 무한다이맥스 무한다이노(키·몸무게 불명)에 원종 950kg이 나왔다. `null`에는 "폼에 그 필드가 없다"와 "값이 불명이다" 두 의미가 섞여 있으므로, **폼 객체의 존재 여부**로 분기해 폼이 있으면 `null`도 그대로 전달한다.

## 📱 반응형

게이지가 있는 두 행(포획률·성비)은 뷰포트에 따라 배치가 다르다.

- **데스크톱**: 값과 게이지를 가로로 — `45 / 255 [게이지]`, `수컷 87.5% [막대] 암컷 12.5%`
- **모바일**: 텍스트를 위, 게이지를 아래로 2단 배치

모바일 375px에서는 라벨 폭을 빼면 가용 폭이 좁아 막대가 70px 남짓으로 줄어든다. 비율을 읽기 어려워지므로 2단으로 내려 막대가 전체 폭을 쓰게 했다.

## 🖥️ 데스크톱 정보 밀도 조정

카드가 2장 늘면서 데스크톱 페이지가 길어져, 함께 정리했다.

- **정보 카드 본문 폰트 20px → 16px.** 기본 정보·특성·신체 정보·육성·포획 정보 카드의 `dt`/`dd`에 해당한다. 원래 16px이던 특성 설명 등은 그대로 두고, 20px이던 것만 낮춰 카드 안 텍스트 크기를 하나로 맞췄다. 모바일은 변경 없다.
- **습득 기술 미리보기 데스크톱 10개 → 5개.** 모바일과 같은 개수가 됐다. 뷰포트별 분기가 필요 없어져 `useDevice` 의존과 상수 2개를 하나로 정리했다. 전체 목록은 그대로 moves 하위 페이지가 담당한다.

## 🔧 백엔드 연동 과정에서 잡은 것

착수 전 introspection과 실제 쿼리로 응답을 확인하는 과정에서 문제 몇 건을 찾아 백엔드와 정리했다.

- **노말폼 크기를 받을 경로가 없었다.** 노말폼 타입이 `PokemonNormalFormList`(필드는 있으나 데이터가 전수 `null`)와 `PokemonNormalForm`(데이터는 오나 필드가 없음)으로 갈려 있었다. 원인은 노말폼에 붙은 `pokeapi_id`가 실제로는 `-gmax` 폼을 가리킨 매칭 오류였고, 프론트가 실제로 쓰는 `PokemonNormalForm`에 필드를 추가하는 것으로 정리했다.
- **노말폼 크기에 거다이맥스 값이 섞여 있었다.** 스트린더·마휘핑·우라오스 3종에서 노말폼 크기가 해당 종의 거다이맥스 수치와 동일했다(우라오스 일격의 태세가 29m/1000kg). 거다이맥스 레코드 34건 중 33건의 `weight`가 `10000` 상수인 점을 근거로 오염임을 특정했다.
- 항상 `null`이던 `PokemonDetail.normalForms`는 미사용 필드로 확인돼 쿼리에서 제거했다.
