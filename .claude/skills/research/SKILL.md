# 리서치 스킬

사용자의 의사결정을 지원하기 위해 외부 정보를 조사하고 보고서 형태로 정리한다.

## 사용 판단 기준

이 스킬은 `context: fork`로 별도 서브에이전트에서 실행된다. 웹 조사 결과는 서브에이전트 컨텍스트에 쌓이고 메인 대화에는 보고서만 돌아오지만, 서브에이전트가 매번 맥락 없이 새로 시작해 토큰 소비가 크다. **작업 규모에 맞는 도구를 선택**해야 한다.

### 메인 대화에서 직접 처리 (이 스킬 사용 X)

- 단순 질문/비교: "A와 B 차이가 뭐야?", "X 라이브러리 장단점 알려줘"
- 1~2개 공식 문서 확인으로 충분한 경우
- 기존 보고서(`research/`)에 이미 조사된 내용인 경우

### 이 스킬 사용 (O)

- **보고서 수준**의 체계적 조사가 필요한 경우
- 3개 이상의 기술/도구를 비교 분석해야 하는 경우
- 구조 결정의 근거 자료 수집이 목적인 경우
- 조사 결과를 `research/`에 보존해야 하는 경우

### 에이전트 사용 (도메인 전문가)

- 조사 + 설계 + 구현이 결합된 복잡한 작업인 경우
- 예: "일본어 랜딩 페이지를 SEO 최적화해서 만들어줘" → seo-specialist 에이전트

> **Why:** 서브에이전트는 하네스 문서를 다시 읽고 웹 조사(수천~수만 토큰)를 수행한다. 단순 질문에 띄우면 메인 대화에서 바로 답하는 것보다 몇 배의 토큰이 든다.

서브에이전트는 대화 내용을 보지 못한다. 호출할 때 **조사 주제, 비교 대상, 결정 맥락(무엇을 정하려는지)을 인자로 넘긴다.**

## 조사 우선순위

반드시 아래 우선순위를 따른다:

1. **공식 문서** (최우선) — 해당 기술/도구의 공식 사이트, 공식 가이드, 공식 블로그, RFC/스펙
2. **신뢰도 높은 기술 글** — 검증된 기술 블로그(web.dev, MDN, Smashing Magazine 등), 저명한 개발자 블로그, 공신력 있는 벤치마크
3. **커뮤니티 자료** — Stack Overflow, GitHub Discussions, DEV.to 등 (참고 수준)

출처가 불명확하거나 신뢰도가 낮은 자료는 근거로 사용하지 않는다.

## 조사 프로세스

1. 호출 인자로 받은 조사 주제와 결정 맥락을 파악한다
2. WebSearch/WebFetch를 활용하여 공식 문서를 우선 탐색한다
3. 공식 문서에서 충분한 정보가 없으면 신뢰도 높은 기술 글을 추가 탐색한다
4. 수집한 정보를 보고서 형태로 정리한다

## 보고서 저장

서브에이전트는 보고서 본문을 반환하고 **파일로 저장하지 않는다.** 메인 세션이 사용자에게 저장 여부를 확인한 뒤(CLAUDE.md "문서를 작성할 때") `.claude/research/tech/YYYY-MM-DD-{주제}.md`로 저장한다. `{주제}`는 kebab-case 요약이다(예: `nextjs-vs-remix`). 파일명 규칙의 권위 원본은 `.claude/research/index.md`다.

> **Why:** 서브에이전트는 실행 중에 사용자에게 물을 수 없다. 저장 판단을 메인 세션에 남겨야 "문서는 작성 전 사용자 확인" 규칙이 지켜진다.

## 주의사항

- 이 스킬은 **코드를 작성하지 않는다**. 조사와 보고만 수행한다.
- 추측이나 의견을 사실처럼 서술하지 않는다. 확인된 사실과 의견을 명확히 구분한다.
- 참고 자료의 URL은 실제로 접근 가능한지 확인한 것만 포함한다.
- 조사 결과가 `.claude/decisions/architecture.md`의 현재 결정과 충돌하면 해당 절을 명시하고 차이점을 설명한다.
