# 검증 옵션 상세

`/create-pr` Phase 3에서 사용자가 선택한 옵션을 실행하는 방법이다. 선택지 제시는 SKILL.md가, 실행 절차는 이 문서가 담당한다.

## QA 종합 검증

`qa-orchestrator` 에이전트에 위임한다. 검사 선별·병렬 실행·통합 판정을 에이전트가 수행한다.

```
Agent({
  subagent_type: "qa-orchestrator",
  prompt: "대상 브랜치 {대상 브랜치} 기준으로 QA 검증을 수행하세요."
})
```

**판정별 처리:**

| 판정           | 처리                                             |
| -------------- | ------------------------------------------------ |
| ⛔ 수정 필요   | 차단 항목을 보고하고 **PR 생성을 중단**한다      |
| ⚠️ 조건부 진행 | 권장 항목을 보고하고 계속 여부를 사용자에게 확인 |
| ✅ 진행 가능   | 바로 PR 생성 단계로 진행                         |

> **Why 위임하는가:** 검사 절차를 이 스킬에 중복해서 적어두면 스킬 문서(`lint-check` 등)와 이중 관리가 되어 한쪽만 고쳤을 때 어긋난다. 검사 방법은 각 스킬 문서가, 조율은 qa-orchestrator가 단일 권위를 갖는다.

## 정적 분석만

빠른 확인이 필요할 때 사용한다.

```bash
# 변경된 파일 목록
git diff {대상 브랜치}...HEAD --name-only --diff-filter=ACMR

# 린트·포맷 검사는 프로젝트 script 우선
npm run lint

# TypeScript 타입 검사
npx tsc --noEmit
```

**이슈 발견 시:** 에러 목록과 자동 수정 가능 여부를 보고한다. **에러(error)가 있으면 PR 생성을 중단**하고, 경고(warn)는 사용자 판단에 맡긴다.

## E2E 테스트

`.claude/skills/e2e-check/SKILL.md`를 읽고 그 절차(서버 확인 → 흐름 도출 → spec 작성 → 실행 → 실패 분류 → spec 삭제)를 따른다. 사용자가 띄운 개발 서버(`localhost:3000`)와 GraphQL 서버(`localhost:4000`)에 붙어서 돌며, **빌드하지 않는다.**

> **Why 빌드하지 않는가:** 프로덕션 빌드는 운영 API를 호출하고, 개발 서버가 떠 있을 때 빌드하면 `.next`를 공유해 서버가 죽는다. 상세는 `.claude/conventions/guides/testing.md` "실행".

**판정별 처리:**

| 결과      | 처리                                                       |
| --------- | ---------------------------------------------------------- |
| 🔴 회귀   | 실패 목록을 보고하고 **PR 생성을 중단**한다                |
| 🟡 불안정 | 보고하고 계속 여부를 사용자에게 확인                       |
| 실행 불가 | 서버를 띄워 달라고 안내하고 계속 여부를 사용자에게 확인    |

## 결과 요약 형식

```markdown
## 검증 결과 요약

| 검증 항목    | 결과           | 상세                         |
| ------------ | -------------- | ---------------------------- |
| QA 종합 검증 | ⚠️ 조건부 진행 | 🔴 0 · 🟡 3 (seo-audit 스킵) |
| 정적 분석만  | -              | 미선택                       |
| E2E 테스트   | -              | 미선택                       |
```

## 옵션별 비용

| 옵션         | 실행 방식            | 토큰 비용 | 소요 시간         |
| ------------ | -------------------- | --------- | ----------------- |
| 정적 분석만  | Bash 직접 실행       | 낮음      | ~10초             |
| QA 종합 검증 | 에이전트 + 병렬 서브 | 높음      | ~60초 (병렬)      |
| E2E 테스트   | spec 작성 + 실행     | 중간~높음 | 흐름 수에 비례    |

**선택 가이드:**

- 단순 버그 수정, 스타일 변경 → 검증 없이 바로 PR
- 로직 변경이 있는 기능 → 정적 분석만
- 릴리즈 PR·범위가 큰 변경 → QA 종합 검증

QA 종합 검증은 변경 파일에 따라 불필요한 검사를 스킵하므로, 검사를 하나씩 개별 실행하는 것보다 저렴하다. QA 종합 검증에는 `e2e-check`가 포함되므로 "E2E 테스트" 옵션을 함께 고르지 않아도 된다.
