## 1. 기존 홈 비평 (4축)

### 축 1 — 정보 위계

**[Major] 섹션 순서가 서비스 역할과 반대 — 메타 콘텐츠가 도감 진입보다 먼저**
- 현재: `Header → 광고 → 챔피언스 메타 → 오늘의 포켓몬 → 퀴즈 → 광고 → Footer`. 검색 유입 83% 서비스에서 본문 첫 콘텐츠가 특정 유저(대전 유저)에 국한된 챔피언스 메타.
- 근거: RES-001 시사점 5(여정형: 찾아보기→즐기기→경쟁 메타). 또한 홈의 실질 역할인 "허브(카테고리 진입 링크)" 섹션 자체가 홈에 없음.

**[Major] 카테고리 허브 링크가 홈 본문에 전혀 없음**
- 콘텐츠 축 6개 중 타입상성·기술·특성은 홈 본문에서 언급 0. 진입은 헤더 내비/MobileTabBar뿐.
- 근거: RES-001 ② 카테고리 30~40% 홈 시각 노출(Baymard), 시사점 2 허브 직링크 블록.

**[Minor] h2가 임의값 폰트(`text-[2rem]`·`text-[2.5rem]`)** — DS `SectionHeading`(text-3xl desktop:text-4xl) 있음에도 미사용. styling.md 임의값 금지 위반.

### 축 2 — 탐색·동선

**[Critical] 데스크톱 "오늘의 포켓몬" 가로 스크롤의 발견성 미설계**
- `HomeBanner.container.tsx`(desktop): `max-w-[1280px] flex overflow-x-auto`에 카드 10장(총 ≈2,236px). 다음 카드 peek(반쯤 잘림)이 설계되지 않아 우연에 의존. 마우스 사용자에게 가로 스크롤 발견 어려움.
- 근거: RES-001 ② "연속성 착시가 가장 강한 시그니파이어". DS `HorizontalScrollList`가 이미 이 문제를 해결하도록 설계됐는데 미사용(자체 flex 재구현).

**[Major] 폴드 위가 광고로 시작** — Header 직후가 TopBanner. RES-001 권고 2(광고는 폴드 위 콘텐츠를 밀지 않는 위치) 위반.

**[Major] 모바일 섹션 h2에 `sticky top-5`** — 연속 섹션 헤딩이 스크롤 중 중첩/잔류 위험. 헤더 실높이와 무관한 매직넘버. 섹션 안내 h2는 sticky 불필요 → 제거 권고.

**[Minor] 퀴즈 섹션에 `/quiz` 허브로 가는 더보기 동선 부재** — 챔피언스 섹션엔 있는 전체 보기 CTA가 퀴즈엔 없음.

### 축 3 — 반응형·터치

**[Critical] ADR-0007 위반 — UA 서버 분기 + 컴포넌트 2벌**
- `page.tsx`의 `detectUserAgent` → `HomeMobile`/`HomeDesktop` 완전 분리 트리. styling.md "신규 UA 분기 금지·2벌 분리 지양"의 대표 위반 사례. **이번 재설계의 최우선 해결 대상.**

**[Major] 데스크톱 카드 컨테이너 고정 높이 `h-[26rem]`** — 카드 내용 변화(긴 이름 등)에 취약. 높이는 콘텐츠에 위임해야.

**[Major] 모바일 "오늘의 포켓몬"이 `w-[900px] grid-cols-5` 고정** — 데스크톱 그리드를 모바일에 욱여넣고 스크롤로 회피. 모바일 퍼스트 반대. RAM 패턴/가로 스크롤 리스트로 교체 대상.

**[Minor] gutter 불일치** — 챔피언스/배너는 `w-[calc(100%-2.5rem)]+px-2`, 퀴즈는 `px-5`. 섹션별 정렬선 어긋남. `px-5 desktop:px-8` 통일 필요(home-phase-b 결정과 일치).

### 축 4 — 시각 일관성

**[Major] 챔피언스 섹션이 구 `ChampionsTopCard` 사용 — DS `ChampionsCard`와 이원화**
- 구 카드는 자체 임의 스타일 + 구 Tag(WCAG 대비 미달) 사용. DS `ChampionsCard`(story 등록, 셸 공유·티어 아웃라인)로 교체 대상.

**[Major] 퀴즈 카드가 DS `QuizCard` 셸 미사용** — 컨테이너가 `bg-primary-4 rounded-2xl p-6 shadow-lg`를 직접 하드코딩. DS QuizCard의 headingId 슬롯(WCAG 4.1.1 id 중복 해결)도 미적용.

**[Minor] "챔피언스 전체 도감 보기" CTA 인라인 스타일** — DS `LinkButton`이 정확히 이 용도로 존재(story 예시 문구까지 동일)하는데 미사용.

## 2. 새 홈 정보구조(IA)

전제: `page.tsx`는 UA 분기 없이 데이터 3종(dailyPokemon 10 / dailyQuiz 3 / topChampionsPokemons 3)만 페칭 → 단일 `Home` 컴포넌트.

| 순서 | 섹션 | 목적 | 콘텐츠 | 근거 |
|---|---|---|---|---|
| 1 | **이번 주 챔피언스 Top 3** (폴드 위) | 챔피언스 유입 확대(최근 핵심 트래픽) + 주간 갱신 큐레이션 훅 | topChampionsPokemons 3 + 전체 도감 CTA | 시사점 4 + 유입 데이터(사용자 결정 2026-07-03) |
| 2 | **허브 링크 그리드** | 콘텐츠 축 6개 노출 + 내부 링크 권위 분배 | 정적 타일 6개(추가 데이터 불필요) | 시사점 2 |
| — | 광고 TopBanner | (항상 렌더되는 정적 섹션 뒤 = 섹션 2와 3 사이) | — | 권고 2 |
| 3 | **오늘의 퀴즈** | 재방문 훅 승격 | dailyQuiz 3종 | 시사점 3 |
| 4 | **오늘의 포켓몬** | 도감 상세로의 신선한 내부 링크 + 데일리 갱신 | dailyPokemon 10, 가로 스크롤 | 시사점 1·3 |
| — | 광고 BottomBanner → Footer | 기존 유지 | — | — |

- 순서 근거(개정): 최근 챔피언스 페이지 유입이 많아 **챔피언스 Top 3를 폴드 위로 승격**해 상단 노출로 유입을 확대한다(사용자 결정). 챔피언스 Top 3도 주간 갱신되는 **구체적 콘텐츠 샘플**이라 시사점 1("폴드 위 = 범주 링크가 아닌 콘텐츠 샘플")을 그대로 충족하며, Pikalytics(랜딩=메타 대시보드)가 직접적 벤치마크 선례다. 원안의 여정형(시사점 5) 프레임 대신 **트래픽 우선 배치**를 채택 — 대전 유저는 타겟 세그먼트상 1차 타겟이기도 하다.
- 오늘의 포켓몬은 섹션 4로 이동해도 도감 상세로의 데일리 내부 링크 역할(시사점 3의 재방문·크롤 신선도 기여)은 유지된다 — 모바일 사용자 70%가 홈 전체를 훑으므로(RES-001 ②) 하단 배치가 노출 실종을 뜻하지 않는다.
- 폴드 위 CTA: 챔피언스 카드 바로 아래 "챔피언스 전체 도감 보기"(LinkButton primary)가 폴드 안/직하에 노출되는 것이 유입 확대 목적의 핵심 — CTA를 섹션 하단이 아니라 카드 직하에 배치.
- **추가 데이터 필요**: 퀴즈 "연속 참여(스트릭) 상태 노출"은 유저별 히스토리 저장/조회가 없어 1차 범위 제외(향후 확장 후보).

## 3. 섹션별 레이아웃 설계

공통: `main` `max-w-[1280px] mx-auto`, gutter `px-5 desktop:px-8` 전 섹션 통일. 제목은 전부 DS `SectionHeading`, sticky 미사용.

### 섹션 1 — 이번 주 챔피언스 Top 3 (폴드 위)
- 모바일: `SectionHeading` + 부제로 포맷 명시("VGC 더블 기준") → `HorizontalScrollList` + `ChampionsCard` 3장(다음 카드 peek). **카드 직하에 `LinkButton`(primary, showArrow) "챔피언스 전체 도감 보기"** — CTA의 폴드 안/직하 노출이 유입 확대 목적의 핵심.
- 데스크톱: 3장뿐이라 스크롤 대신 `desktop:flex justify-center gap-6` 정적 배치(3~4 스와이프 기준 미달).
- 빈 상태(`length===0 → null`) 시 허브 그리드(정적, 항상 렌더)가 첫 섹션이 되므로 폴드가 광고로 시작하지 않음 — 광고를 섹션 2 뒤에 둔 이유.
- 구 `ChampionsTopCard` 제거, DS `ChampionsCard`로 전면 교체. **신규 후보 없음.**

### 섹션 2 — 허브 링크 그리드
- 모바일: `grid-cols-2 gap-4` 타일 6개(아이콘 + 라벨 + 한 줄 서술형 앵커). 아이콘은 MobileTabBar가 쓰는 기존 SVG 6종 재사용. 타일 전체 Link.
- 데스크톱: `desktop:grid-cols-3` (2행×3열).
- DS 매핑: 맞는 원자 없음 → **신규 후보: `HubLinkCard`** (아이콘+제목+설명 타일 카드. LinkButton은 텍스트 버튼이라 역할 다름). **구현 1순위.**

### 섹션 3 — 오늘의 퀴즈
- 모바일: `QuizCard`(DS 셸) 3장 세로 스택(`grid gap-6`). 기존 컨테이너 로직(이미지/답안 QuizAnswerButton)은 슬롯 주입.
- 데스크톱: `desktop:grid-cols-3`.
- 하단 `LinkButton`(secondary, showArrow) "퀴즈 더 풀어보기" → `/quiz`.
- DS 매핑: SectionHeading + QuizCard(headingId로 WCAG 4.1.1 해결) + LinkButton. **신규 후보 없음.**

### 섹션 4 — 오늘의 포켓몬
- 모바일: `SectionHeading` → `HorizontalScrollList` + `PokemonCard`(variant=pokedex, w-40). 다음 카드 자연 peek.
- 데스크톱: 카드만 `desktop:w-56` 자동 확장, 리스트 구조 동일(5~6장 노출 + 스크롤).
- DS 매핑: SectionHeading + HorizontalScrollList + PokemonCard. **신규 후보 없음.**

## 4. 인터랙션 패턴

- **가로 스크롤 적용: 2곳만** — 섹션 1(챔피언스, 모바일 한정) + 섹션 4(오늘의 포켓몬 10장, 동질). 허브 그리드·퀴즈는 캐러셀 금지(이질적 진입점).
- **peek 구현은 HorizontalScrollList에 위임**(고정폭 flex-shrink-0 특성으로 자연 발생). 자동 넘김 없음.
- 카드 클릭 영역은 카드 전체(Link 래핑, 기존 패턴). 호버 확대는 DS 카드/리스트 레벨에 이미 규정 — 홈에서 재정의 안 함.
- HubLinkCard는 `focus-visible:outline` 필수. 타일 크기가 44px 크게 상회해 별도 min-h 불필요.
- 스크롤 단서: 섹션 1(챔피언스) 하단 마진 과대 금지(`mb-8 desktop:mb-10` 권장) — 허브 그리드 상단 살짝 노출.
- 빈 상태: 챔피언스 `length===0 → null` 유지 — 이 경우 허브 그리드(정적)가 첫 섹션이 되어 폴드 콘텐츠가 보장된다(광고를 섹션 2 뒤에 둔 이유). 오늘의 포켓몬도 동일 가드 추가 권고(기존 미비).

## 5. 광고 슬롯 배치안

- **TopBanner: 섹션 2(허브 그리드) 이후·섹션 3(퀴즈) 이전으로 이동** — 폴드 위는 콘텐츠 우선(RES-001 권고 2). 섹션 1(챔피언스)이 빈 상태 시 null이 되는 동적 섹션이므로, 항상 렌더되는 정적 섹션(허브) 뒤에 둬야 어떤 경우에도 광고가 첫 요소가 되지 않는다.
- **BottomBanner: 현행 유지**(섹션 4 이후, Footer 이전).
- 슬롯 크기/형식 변경 없음 — 기존 배너 컴포넌트 재사용, 위치만 이동.
