# RES-004: AdSense 광고 재도입 배치 전략

- 조사일: 2026-07-28
- 스킬: research (+ ux-designer 에이전트 배치 설계)
- 브랜치: feature/1.54.0-ad-units

## 요약

DS 반응형 개편(A~F 그룹) 과정에서 제거·보류했던 AdSense 광고를 **GA·서치콘솔·애드센스 3지표 종합 우선순위**에 따라 재도입한다. 3지표가 일관되게 가리키는 결론: **상세(detail)와 상성계산기(type-effectiveness)가 트래픽·수익의 축**이며, 배치는 **"콘텐츠 소비 후 섹션 사이" 원칙**을 따른다. 프로젝트 자체 실측(모바일 상세 **하단** 배너 CTR 2.02%·수익 1위 vs **상단** 배너 CTR 0.06% — **34배 차이**)이 이 원칙의 가장 강력한 근거다. 광고 유닛은 콘텐츠 반응형 단일화와 무관하게 **UA별 고정 규격 2벌**(데스크톱 728×90/970×250, 모바일 320×100)을 유지하고, 홈과 동일한 `page.tsx`의 `detectUserAgent` prop 주입 패턴으로 CSR 전환 없이 서버 분기한다.

## 조사 배경

DS 페이지 반응형 개편(2단계, A~F 전 그룹 완료·머지)에서 각 페이지의 UA 분기 2벌 구조를 반응형 단일로 통합하며 **6개 이상 배너 광고를 제거하고 보류**했다(`List.view.tsx`·`Detail.view.tsx` 등에 "반응형 광고 유닛이 정해지면 재도입" 주석 명시). 챔피언스 데이터 원천 변경(PR #195)까지 완료된 뒤, 보류했던 광고 유닛 재도입에 착수한다(2026-07-28 사용자 결정).

재도입 착수 전 선행 분석으로 (1) 3지표 데이터 종합, (2) 광고 코드 현황 조사, (3) ads.txt 서빙 확인, (4) 각 페이지 UI 실측 기반 배치 설계를 수행했다. 본 보고서는 그 결과를 실행 계획으로 정리한 것이다.

## 조사 내용

### 1. 3지표 종합 — 페이지별 우선순위

분석 데이터(3개월, 2026-04-27 ~ 07-26): GA4 페이지 조회수, 서치콘솔 페이지별 검색 성과, 애드센스 유닛별 수익. 라우트 그룹별 집계 결과:

| 순위 | 페이지 | GA 조회 | 검색 클릭 | 애드센스 수익 | 종합 판단 |
|------|--------|--------:|----------:|--------------:|-----------|
| 1 | **detail 상세** | 48.8% | 18.2% | 40.8% | 조회·수익 모두 1위. 압도적 최우선 |
| 2 | **type-effectiveness** | 9.0% | 58.3% | 32.1% | 검색 유입 1위(관문)·수익 2위 |
| 3 | **moves 기술** | 11.9% | 5.0% | 7.8% | 조회 2위, 균형 |
| 4 | **champions** | 10.7% | 5.4% | 3.5% | 조회 3위. 신규 배치 대상(사용자 요청) |
| 5 | **list 도감** | 13.3% | 0.2% | 4.3% | 조회 많으나 검색 유입 거의 없음(내부 탐색) |
| - | 홈 | (list 합산) | 8.1% | 7.6% | 이미 광고 있음 |

| - | ability | 1.2% | 0.9% | 2.0% | 롱테일 |

- 기기: 모바일 46% / 데스크톱 46% / 태블릿 3% — **모바일·PC 반반**, 양쪽 유닛 모두 필요.
- 국가: 한국 99% — 수익 최적화는 국내 기준.
- 검색 유입의 절반 이상이 `/type-effectiveness` 단일 페이지(클릭 31,814 / 노출 415,952 / CTR 7.65%).

### 2. 광고 코드 현황

- **인프라 전부 생존**: 스크립트 로더([layout.tsx](../../src/app/layout.tsx), publisher `ca-pub-6481622724376761`), 푸시 훅([useAdSlotEffect.ts](../../src/hook/useAdSlotEffect.ts)), 광고 컴포넌트 38개([components/adSlot/](../../src/components/adSlot/)) 모두 온전.
- **실제 렌더는 홈(`/`)의 4개뿐**. 나머지 34개는 파일은 남았으나 어디서도 import되지 않는 dead 상태. DS 개편 때 각 뷰/컨테이너에 "재도입 예정" 주석과 함께 사용처에서만 제거됨.
- **재사용 가능**: dead 컴포넌트는 홈에서 동작 중인 것과 100% 동일 패턴(`'use client'` + `useAdSlotEffect()` + `<ins className="adsbygoogle">`). 다시 import·render만 하면 즉시 동작.
- **걸림돌**: (a) 컴포넌트가 UA 2벌·슬롯 ID 하드코딩·props 없음 → 유연 재사용엔 `<AdUnit slot format>` 리팩터링 여지, (b) [adSense.ts](../../src/constants/adSense.ts)의 `ADSENSE_CLIENT`/`ADSENSE_SLOT` 상수는 dead(미사용).
- **슬롯 불일치**: 대시보드엔 있으나 코드에 없는 슬롯 10개, 코드엔 있으나 대시보드 목록에 없던 슬롯 11개(주로 quiz/결과) — 재도입 전 정리 필요.

### 3. ads.txt — 조치 불필요

`https://poke-korea.com/ads.txt`는 **정상 서빙 중**(HTTP 200, `text/plain`, CloudFront CDN 직접 제공, Last-Modified 2025-06-20). 본문 `google.com, pub-6481622724376761, DIRECT, f08c47fec0942fa0`의 publisher ID가 코드와 일치. 저장소 `public/`엔 없지만 인프라(CDN)로 관리되는 파일이라 정상. **재도입 백로그에서 제외**.

### 4. 광고 매체 제약 (일반 UI와 다름)

- **UA별 고정 규격 2벌 유지가 원칙**. 데스크톱은 height 명시(728×90·970×250) — 반응형 `auto`는 데스크톱에서 CLS 유발. 모바일은 320×100. 콘텐츠 뷰는 반응형 단일이되, 그 안의 광고 슬롯만 `useDevice()`의 `isMobile`로 분기 렌더.
- **숨김 렌더(CSS `hidden`) 금지**: 미노출 유닛을 DOM에 push한 뒤 CSS로 숨기는 것은 AdSense 정책 위반. 따라서 CSS 반응형 분기 불가 → `page.tsx`에서 `detectUserAgent`로 한쪽만 서버 선택해 주입(홈의 현행 패턴). 이 방식은 서버가 판별한 값을 prop으로 넘기므로 **CSR 전환이 발생하지 않는다**([Device.context.tsx](../../src/context/Device.context.tsx)는 state 없는 값 전달자).

## 비교 분석 — 배치 설계 (페이지별)

배치 원칙은 실제 캡처 화면(PC/Mobile × 5페이지) 기반 ux-designer 설계 결과다.

### 배치 원칙 (전 페이지 공통)

1. **폴드 상단 배치 금지** — 실측 CTR 34배 차이 + NN/G 배너 실명 연구(사용자는 광고 학습 위치를 무의식 회피).
2. **섹션 경계에만 삽입** — 표·카드그리드·캐러셀 "내부" 삽입 금지(접근성 구조 훼손·유지보수 리스크, WCAG 1.4.10).
3. **UA 분기는 홈 패턴 계승** — `ReactNode` prop 주입 + `page.tsx` `detectUserAgent`.
4. **데스크톱 고정 height / 인아티클·인피드는 fluid + `min-height` 예약**(CLS 방지).
5. **모바일 하단 배너는 탭바(`h-16`, 64px)와 `pb-16`으로 분리**, `fixed` 금지.
6. **밀도 상한**: 모바일 페이지당 최대 3개, 3순위 이하 1~2개.

### 1차 도입 최소셋 (데이터 근거가 강한 지점만)

| 페이지 | 위치 | PC 규격 | Mobile 규격 |
|--------|------|---------|-------------|
| detail | 능력치 ↔ 기본정보 사이 | 인아티클 fluid | 인아티클 fluid |
| detail | 기술표 ↔ 타입상성 사이 | 인아티클 fluid | 인아티클 fluid |
| detail | 최하단(진화체인 아래, 탭바 위) | 디스플레이 970×250 | 디스플레이 320×100 |
| type-effectiveness | 상성표 ↔ 타입별추가효과 사이 | 인아티클 fluid | 인아티클 fluid |
| moves 상세 | 히어로 ↔ 포켓몬그리드 사이 | 인아티클 fluid | 인아티클 fluid |
| champions 홈 | 자주보이는포켓몬 ↔ 인기조합 사이 | 인아티클 fluid | 인아티클 fluid |
| champions 홈 | 최하단(최근대회 ↔ 퀵링크 사이) | 디스플레이 970×250 | 디스플레이 320×100 |

### 2차 확장 (지표 확인 후)

- type-effectiveness: 타입선택 ↔ 상성표 사이(플로우 차단 리스크 → A/B 검증)
- moves 목록: 카드 그리드 인피드(데스크톱 20번째·모바일 8번째 카드)
- champions 홈: 인기조합 ↔ 최근대회 사이 인아티클 / champions 상세: 메타패널 아래 / champions 티어: 티어 그룹 사이
- list: 카드 그리드 인피드(최하위, `List.view.tsx`의 기존 제거 결정 재검토 필요)

## 결론 및 추천

### 권고 사항

1. **구현 순서는 우선순위대로, 한 페이지씩 단계별 확인** — detail → type-effectiveness → moves 상세 → champions 홈. 각 페이지 구현 후 실제 캡처로 검증 후 다음 페이지 진행.
2. **UA 분기는 홈 패턴을 그대로 계승** — 뷰가 `topBanner`/`inArticleAd` 등을 `ReactNode` prop으로 받고, `page.tsx`가 `detectUserAgent`로 한쪽만 주입. 신규 상태 관리 도입 불필요.
3. **1차는 최소셋만** — 데이터 근거가 강한 7개 슬롯. list는 1차 제외(5순위·내부 탐색). 지표 안정화 후 2차 확장.
4. **champions 신규 배치는 1차에 2개 포함** — 사용자 요청 반영. 단 GA 조회 4위이므로 밀도는 홈 3개·상세 1개로 제한(트래픽 대비 과잉 광고 방지).

### 고려 사항

- **CLS**: 데스크톱 인아티클(fluid)은 `min-height` 플레이스홀더 필수. 데스크톱 디스플레이는 고정 height라 문제 없음.
- **모바일 탭바 겹침**: 하단 배너는 콘텐츠 스택 마지막 정적 요소로, 탭바와 `pb-16` 분리.
- **list 재도입은 결정 번복**: [List.view.tsx](../../src/views/list/List.view.tsx)에 "사용자 결정으로 제거(2026-07-07)" 주석 존재. 재도입 시 근거(조회 13.3% 규모) 명시 후 진행.
- **슬롯 정리**: 코드/대시보드 슬롯 불일치(10개+11개)는 구현 시 실제 사용할 슬롯 ID를 대시보드와 대조해 확정.
- **상수 SSOT화(선택)**: 재도입을 계기로 하드코딩 슬롯 ID를 `adSense.ts` 상수로 통합할지 검토(관리 편의 vs 작업 범위 확대 트레이드오프).
