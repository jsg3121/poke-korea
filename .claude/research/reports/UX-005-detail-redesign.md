# UX-005: 포켓몬 상세 페이지(/detail/[pokemonId]) 전면 재설계

- 작성일: 2026-07-09
- 에이전트: ux-designer
- 입력: [RES-003](RES-003-detail-page-reference.md) + 현행 `/detail` 코드(container/desktop·mobile) + 실화면 캡처(2026-07-09 프로덕션) + DS 인벤토리
- 범위: 설계만(코드 미작성). 반응형 단일(ADR-0007)·모바일 퍼스트·DS 조립 전제. 홈(PR #179)·리스트(PR #180) 개편 확립 패턴 계승(크롬만 UA 허용, gutter px-4, 광고 배치는 잠정 제외)

## 1. 기존 상세 페이지 비평 (4축)

### 🔴 Critical

**C1. 폼 전환 배지가 레이더 카드 위에 겹쳐 라벨이 잘림 (실캡처 3건 확인)**

- 데스크톱 폴드 화면에서 이로치·메가진화·거다이맥스 아이콘 버튼이 우측 레이더 스탯 카드 좌측 모서리와 겹쳐 라벨 텍스트가 카드 테두리에 걸려 잘린다. 메가·거다이맥스 캡처에서 동일 재현.
- 원인(코드 확인): `MegaSwitch`/`GigantamaxSwitch`가 `absolute` + 음수 `left`(`-left-11` 기본 → hover 시 `-left-28`/`-left-32`)로 "아이콘만 노출 → hover 시 라벨 슬라이드 인" 인터랙션을 구현하는데, 이 슬라이드 트랙이 옆의 레이더 카드(`absolute`, `w-[25rem]`)와 겹치는 좌표에 위치한다.
- 근거: 인터랙티브 요소가 다른 카드의 시각적 경계를 침범하는 것은 레이아웃 격리 원칙 위반이며, hover 의존 라벨은 터치 디바이스에서 발견 불가능.
- 개선안: 폼 전환 UI를 절대위치 슬라이드 대신 **레이더 카드와 별도 flow 영역의 상시 라벨 칩 그룹**으로 재설계(§2 — 데스크톱도 모바일과 동일하게 라벨 있는 칩으로 통일). 좌표 계산이 필요한 애니메이션 자체를 제거해 재발 여지를 없앤다.

**C2. 모바일 배지가 기본정보 라벨(dt)을 침범 (실캡처 2개체 확인)**

- 메가 모바일 캡처에서 "애니메이션 및 만화" 참고문헌 배지가 "등장 세대" `dt` 라벨 위에 겹쳐 텍스트가 뭉갠다. 피카츄 모바일에서도 "수집용 카드게임(CCG)" 배지가 "전국도감번호" 라벨과 겹침 — 최소 2개체·2배지 조합에서 확정 재현.
- 원인(구조적 추정): `dl` 항목이 `h-12` 고정 높이인데, 참고문헌 배지가 `dt` 텍스트 옆 인라인으로 삽입되며 배지 폭이 라벨 컬럼 폭을 초과 → 다음 줄로 밀리며 아래 행과 겹침.
- 근거: WCAG 1.4.10(Reflow) — 텍스트가 겹쳐 읽을 수 없는 상태는 콘텐츠 손실.
- 개선안: 배지를 `dt` 라벨 뒤 인라인이 아니라 **`dd` 값 뒤 또는 카드 우상단 고정 아이콘**으로 이동. 고정 `h-12`를 `min-h-12` + `flex-wrap`으로 전환.

**C3. 레이더 차트는 접근성 차단 수준 — canvas 렌더 + 수치 텍스트 DOM 부재**

- `StatChartComponent`는 Chart.js `Radar`(canvas)로 렌더되며 `aria-label="포켓몬 능력치 차트 그래프"` 하나만 존재. 각 스탯 수치는 canvas 픽셀로만 표현되고 스크린리더가 읽을 DOM 텍스트가 없다(보이는 숫자도 Chart.js `pointLabels`로 canvas 내부에 그려짐).
- 근거: WCAG 1.1.1(Non-text Content) — 요약 alt 하나로는 6개 개별 수치를 전달하지 못함. RES-003도 "canvas보다 DOM 기반 막대가 접근성 우위" 확인(벤치마크 중 레이더 사용 0곳).
- 개선안: §5 결정 1 참조 — 막대 전환 시 자동 해결. 레이더 유지 시에도 최소한 차트와 별도로 스크린리더가 순회 가능한 DOM 텍스트(표) 병행 필수.

### 🟡 Major

**M1. 데스크톱/모바일 폼 전환 UI 완전 불일치** — 데스크톱: 아이콘 전용 + hover 라벨 슬라이드(C1과 얽힘) / 모바일: 라벨 상시 칩. 동일 기능의 발견 가능성이 뷰포트에 따라 다른 일관성 위반. 개선: 데스크톱도 "상시 라벨 칩"으로 통일 — 동일 컴포넌트, 배치만 반응형.

**M2. 이전/다음 포켓몬 내비게이션 완전 부재** — 기존 `PrevFormButton`/`NextFormButton`은 이름과 달리 같은 종의 폼 간 이동 전용. RES-003 벤치마크 4/5가 상단 이전/다음 내비 보유, SEO 관점에서도 `<a href>` 순차 링크가 공식 권장. 개선: 종(種) 단위 이전/다음 내비 신설, 폼 전환과 완전 분리.

**M3. moves 하위 페이지 데스크톱에 대형 미사용 여백 (실캡처 확인)** — 상단 정보 카드와 "기술 목록" 사이 약 300px+ 공백. `h-[20rem]`(320px) 고정 광고 슬롯이 광고 미렌더 시 빈 공간으로 남아 핵심 콘텐츠를 첫 화면 밖으로 밀어냄. 개선: 광고 미노출 시 슬롯 collapse(조건부 렌더) — 광고 반응형 유닛 재도입은 별도 트랙이므로 이번엔 슬롯 축소만 최소 반영.

**M4. 모바일 기술 표가 1기술=1카드 세로 스택으로 부피 과대** — 기술 1개당 약 220px, 리자몽 레벨업 기술만 15개+. 벤치마크 중 설명 문구까지 카드에 포함해 부피를 키우는 곳은 없음. 개선: 가로 스크롤 표(첫 열 고정)로 전환(RES-003 권고 5 채택).

**M5. UA 분기 2벌 렌더 + ISR 무의미화 (ADR-0007 위반, 리스트 개편과 동일 모순)** — container/desktop·mobile 약 26개 파일 완전 중복. `revalidate=31536000`인데 `headers()` UA 감지로 사실상 동적 렌더. 개선: 반응형 단일 컴포넌트로 통합.

### 🟢 Minor

**m1. 진화 체인이 순수 이미지 나열로 클릭 대상 불명확** — 카드/버튼 어포던스 부재. 개선: PokemonCard류 셸 적용.

**m2. 퀴즈 배너가 2회 반복 삽입되어 콘텐츠 흐름을 끊음** — 특성 직후 + 타입 상성 직후. 개선: 1곳으로 통합 또는 시각 강조 축소(§5 결정 3).

**m3. 데스크톱 첫 화면에서 스탯 카드가 식별 정보와 시각적 비중 경쟁** — 레이더 카드(25rem 정사각)가 이미지 위에 떠 있어 "식별 정보 우선" 원칙과 어긋남. 개선: 스탯 영역을 식별 정보 아래로 재배치.

## 2. 새 IA 제안

### 공통 원칙 (RES-003 채택)

단일 세로 스크롤 유지, 탭 분할 금지. 첫 화면 = **이미지 + 번호/이름 + 타입**(식별 정보) 우선, 스탯·상세 데이터는 그 아래. 폼 전환은 데/모 동일한 "상시 라벨 칩" 패턴(hover 의존 슬라이드 제거).

### 모바일 섹션 순서 (375px 기준)

```text
전역 헤더(h-12, 크롬)
 ├─ [◀ 이전: No.005 파이리]  [다음: No.007 어니부기 ▶]   ← 신규, 종 단위 내비 (M2)
 ├─ 히어로 (타입색 그라데이션 + 일러스트, 유지)
 ├─ 이름 + 도감번호 + 타입 칩                            ← 식별 정보 승격
 ├─ 폼 전환 칩 로우 (이로치/메가/거다이맥스 — 라벨 있음)
 ├─ 스탯 카드 (레이더 유지 시 DOM 텍스트 병행 필수, §5)
 ├─ [광고 슬롯 — 위치만 표시, 도입은 별도 트랙]
 ├─ 기본정보 카드
 ├─ 특성 카드
 ├─ (특성 퀴즈 배너 — 통합 위치는 §5 결정 3)
 ├─ 레벨업 기술 (가로 스크롤 표, 첫 열 고정 — M4)
 ├─ 머신 기술 (동일)
 ├─ 타입 상성 (강점/약점 토글 유지)
 ├─ (상성 퀴즈 배너)
 ├─ 진화 체인 (클릭 어포던스 있는 카드 셸 — m1)
 └─ [광고 슬롯]
```

### 데스크톱 섹션 순서 (1280px 기준)

```text
전역 헤더(고정) + 서브네비
 ├─ [◀ 이전: No.005 파이리]  [다음: No.007 어니부기 ▶]   ← 신규, 상시 노출
 ├─ 히어로: 좌측 일러스트 / 우측 이름+번호+타입+폼 전환 칩(라벨 상시 — M1)
 ├─ 스탯 카드 (히어로 하단, 별도 flow 영역 — C1·m3)
 ├─ [광고 슬롯]
 ├─ 기본정보 | 특성 (2컬럼, 유지)
 ├─ (특성 퀴즈 배너)
 ├─ 레벨업 | 머신 기술 (2컬럼, 유지 — 데스크톱 표는 벤치마크 3/5와 일치)
 ├─ 타입 상성
 ├─ (상성 퀴즈 배너)
 └─ 진화 체인
```

### RES-003 6개 권고 채택/기각 판단

| # | 권고 | 판단 | 근거 |
|---|------|------|------|
| 1 | 단일 세로 스크롤, 탭 분할 금지 | **채택** | 현행 유지 확인. Baymard 실증(가로 탭 발견성 실패)과 부합 |
| 2 | 이전/다음 포켓몬 내비 신설 | **채택** | 현재 완전 부재(M2). 종 단위 신설 + 폼 전환과 물리적 분리로 "폼 URL 내비 오염" 원천 차단 |
| 3 | 레이더 → 가로 막대+수치 병기 | **보류 — 사용자 결정(§5)** | 접근성·벤치마크 근거는 막대 우위 명확하나, 레이더는 서비스 시각 아이덴티티일 수 있어 설계자 단독 결정 범위 밖 |
| 4 | 폼 변형 경로 분리 유지 + 메타 강화 | **채택(UX 관점 지지)** | 경로 구조는 이번 트랙 변경 대상 아님. 폼별 메타/alt 강화는 seo-specialist 협업 |
| 5 | 모바일 기술 표 가로 스크롤 전환 | **채택** | M4 해결책. 부피 절감 명확 + 벤치마크 다수 일치 |
| 6 | 스티키 앵커 내비 도입 | **기각(이번 트랙 미도입)** | 섹션 8~9개 수준·페이지 길이 3.5~4화면으로 리스트급이 아님. 스티키 총높이 관리 복잡도 대비 이득 작음. 콘텐츠 증가 시 재검토 |

## 3. DS 컴포넌트 매핑

| 섹션/요소 | 기존 DS 조립 | 신규 규격화 후보 |
|---|---|---|
| 이전/다음 내비 | LinkButton 조립(44px 터치 타깃, 텍스트+화살표) | 없음 |
| 폼 전환 칩(라벨 상시형) | Chip 원자 베이스로 selected 상태 조립 우선 | 조립 실패 시 `FormSwitchChip` 최소 규격화 |
| 기본정보/특성 카드 셸 | 기존 `card-detail` 유틸 클래스 재사용 | 없음 |
| dt/dd 행 겹침 수정 | 레이아웃 버그 수정만 | 없음 |
| 스탯 시각화(막대 전환 시) | 없음 | **StatBar**(스탯명+수치 텍스트+막대, DOM 기반. §5 결정 후) |
| 모바일 기술 표(가로 스크롤) | 없음 | **MoveTable**(반응형 단일: 데스크톱 일반 표 / 모바일 첫 열 고정 가로 스크롤, ARIA 보정) |
| 타입 상성 토글 | 기존 `InfoContentComponent` 로직 재사용(데/모 통일만) | 없음 |
| 진화 체인 카드 | **PokemonCard(+Shell)** 재사용 | 없음 |
| 참고문헌 배지 | 배치 변경 우선 | 필요 시 `SourceBadge`(선택) |
| 광고 슬롯 | adSlot 기존 패턴 + 조건부 collapse만 추가 | 없음 |

신규 컴포넌트는 **StatBar(조건부)·MoveTable·FormSwitchChip(조건부)·SourceBadge(선택)** 4종 이하로 최소화. 나머지는 기존 조립/레이아웃 수정.

## 4. 범위/단계 — 구현 단계 순서

### 트랙 A — `/detail/[id]` 본문(폼 변형 포함), 우선 착수

1. **시각 결함 긴급 수정(C1·C2)** — 폼 전환 슬라이드 제거 + 라벨 상시 노출(데/모 통일), 배지 위치 이동. 구조 변경과 무관한 국소 수정이라 선행 가능
2. **UA 분기 제거 + 반응형 단일화(M5)** — 컨테이너 26개 파일 통합, 리스트 개편 확립 패턴 재사용
3. **이전/다음 종 내비 신설(M2)** — `<a href>` 구현(SEO 크롤 경로 동시 충족)
4. **히어로 재배치** — 이름+번호+타입 승격, 스탯 카드 별도 flow 분리(m3, C1 재발 방지 전제)
5. **진화 체인 카드 셸 적용(m1)** — PokemonCard 재사용
6. **퀴즈 배너 통합(m2)** — §5 결정 3 반영
7. **스탯 시각화 전환(§5 결정 1 이후)** — 막대 전환 시 StatBar 신규 + C3 해결 / 레이더 유지 시 DOM 텍스트 병행만

### 트랙 B — `/moves` 하위 페이지, 후속 분리

1. **광고 슬롯 조건부 collapse(M3)**
2. **모바일 기술 표 가로 스크롤 전환(M4)** — MoveTable 신규
3. **UA 분기 제거** — moves 하위 라우트 전체
4. **버전 그룹 라우트 canonical 검토** — RES-003 SEO 권고, seo-specialist 별도 협의

분리 근거: 본문의 Critical(C1~C3)이 가장 시급하고 `/moves`는 별도 라우트라 독립 배포 가능 — 리스트 개편의 `?page=N` 후속 트랙 분리와 동일한 판단 기준.

## 5. 사용자 결정 필요 항목

### 결정 1 — 스탯 시각화: 레이더 유지 vs 가로 막대 전환

| 선택지 | 장점 | 단점 |
|---|---|---|
| **A. 레이더 유지 + DOM 텍스트 병행** | 브랜드 비주얼 보존, 구현 비용 최소 | 벤치마크 5/5 미사용 패턴, canvas 모바일 공간 비효율 지속, 접근성은 "우회 지원"에 머무름 |

권고: 근거는 B 우세하나 브랜드 아이덴티티 판단은 사용자 몫.

### 결정 2 — 참고문헌 배지 존치/위치

배지 종류가 소수 고정이면 `dd` 값 옆 인라인으로 충분, 늘어날 예정이면 카드 우상단 고정 아이콘+툴팁(SourceBadge)이 확장성 있음. 데이터 소스 확장 계획 확인 필요.

### 결정 3 — 퀴즈 배너 통합 위치

(a) 특성 직후 1곳 유지 + 상성 직후 제거 / (b) 페이지 최하단 1곳 이동. 특성 퀴즈와 상성 퀴즈는 콘텐츠 성격이 달라 완전 통합이 어려워, 어느 쪽을 남길지는 퀴즈 유입 기여도(비즈니스 우선순위)에 달림.
