## 1. 개요

D그룹은 `/type-effectiveness` 1라우트, 정적 페이지(데이터 페칭 없음)다. 구성은 **① 타입 선택 계산기 → ② 계산 결과(추천/주의 타입 + 도감 링크) → ③ 18×18 전체 상성표 → ④ 타입별 추가효과 설명** 4블록. A~C그룹과 달리 목록/상세형 카드 그리드가 아니라 **"입력(타입 선택) → 즉시 계산 결과"라는 계산기형 인터랙션**이 핵심이라, 이번 그룹의 설계 축은 카드/필터 DS가 아니라 **선택 컨트롤 시맨틱(TypeChip)과 상세 페이지 DS(TypeMatchup)의 재사용 여부**에 있다. 이 페이지는 상세 페이지가 만든 `TypeMatchup`이 등장한 이후 처음으로 "같은 데이터 형태(`calculateRelationType` 산출값)를 소비하는 두 번째 소비처"이므로, 보류 트랙 "TypeMatchup 상성계산기 재사용"의 실제 판단 시점이다.

## 2. 기존 화면 현황 분석 (4축 비평)

실캡처 기준(2026-07-20, desktop 1440·mobile 390 fullPage, `.claude/playwright/screenshots/09-type-effectiveness-{desktop,mobile}.png`).

### Critical

**C1. 모바일 18×18 상성표가 실질적으로 읽을 수 없는 상태 (실캡처 확정)**
- 문제: 모바일(390px)에서 표 전체 폭이 뷰포트 안에 욱여넣어져(`w-full` + `table-fixed`, 가로 스크롤 없음) 셀 하나가 약 15px 폭으로 압축된다. "0.5배"가 2줄로 강제 개행되고, 행/열 헤더(타입명)도 "고스트"·"드래곤"이 세로로 쪼개져 읽힌다.
- 근거: WCAG 1.4.10(Reflow) — 지금은 스크롤은 없지만 대신 텍스트 자체가 분해되어 정보 손실. NN/g 표 반응형 가이드 — "축소된 표는 가로 스크롤이나 재구성이 필요하며, 텍스트를 억지로 욱여넣는 것은 최악의 선택".
- 개선안: §3 질문3 — 가로 스크롤 + sticky 첫 행/열로 전환, 셀 최소 폭 확보.

**C2. 계산기 선택 상태의 시각적 대비가 매우 약함 (실캡처 확정)**
- 문제: 선택된 타입 버튼(`opacity-100`)과 미선택(`opacity-60`)의 차이가 육안으로 거의 구별되지 않는다. 선택 표시가 투명도 하나에만 의존.
- 근거: NN/g "Visibility of System Status" — 핵심 과업(타입 선택)의 결과를 즉시 명확히 인지해야 한다. WCAG 1.4.1(단일 채널 정보 전달)에도 근접.
- 개선안: §3 질문1 — TypeChip DS(active 시 grayscale→컬러+볼드, 명확한 on/off 대비) 재사용.

### Major

**M1. UA 분기 2벌 렌더 + 실효 없는 `revalidate` (ADR-0007 위반)**
- `revalidate=1년` 선언하지만 `headers()` UA 분기로 요청마다 동적 렌더. desktop/mobile 컨테이너 9파일씩 총 18파일이 거의 동일한 채 복제(`Caculator` 오타·`groupt` 오타까지 별도 유지보수). → 반응형 단일 통합, revalidate 제거.

**M2. 결과 표시가 도감의 타입 배지 시각 언어와 완전 불일치**
- `TypeResultChip`은 `CardColor` 인라인 헥사, TypeMatchup은 `grade-*` 토큰 + `TagComponent` — 같은 개념(타입 배지)의 시각 문법이 3종으로 파편화. → TagComponent/토큰 기반 통일(§3 질문2).

**M3. 임의값·비토큰 색 도배**
- `text-[2rem]`·`text-[1.75rem]`·`text-[#8b8b8b]`·`text-[#333333]`·중요도 배경 5종 임의 헥사(`#feb0b0`·`#ffae76`·`#ffdf61`·`#84efff`·`#80f7ac`). → 폰트 스케일 토큰 + `grade-*`(danger/warning/good/better/best) 치환. 임의 헥사 5종은 grade 토큰과 1:1 대응(quad→danger, double→warning, half→good, quarter→better, zero→best).

**M4. 계산기(5단계 배율)와 표(4단계 배율)의 개념 모델 불일치**
- 표는 단일 타입 대 단일 타입이라 0/0.5/1/2배만 존재, 4배/0.25배는 2타입 조합에서만 발생하는 파생값. 결함은 아니나 혼동 소지 → 표 캡션에 "단일 타입 기준" 명시.

### Minor

- **m1.** "최대 2개" 제약이 선택 완료 후에야 안내됨 → 상시 보조문구로 선제 고지
- **m2.** "초기화"가 타입 목록 ul 안 19번째 li로 섞임 → 별도 액션 슬롯 분리
- **m3.** 타입 미선택 시 결과 섹션 미렌더(빈 상태 부재) — 계산기가 즉시 인터랙션이라 EmptyState 불필요, 선택 유도 힌트만 검토
- **m4.** 상성표 배율 필터가 텍스트 색 변화만으로 표현(버튼 어포던스 부재) → 토글 버튼 스타일 보강

## 3. 핵심 질문 결정 + 근거

### 질문 1 — 타입 선택 UI

**결정: `TypeChip` DS를 `mode='multi'`(max2 잠금은 호출부)로 재사용. 신규 규격화하지 않는다.**

| 근거 | 설명 |
|---|---|
| 동일 요구사항 | 도감 리스트 FilterBar가 이미 "multi + max2 잠금(disabled)"을 같은 방식으로 사용 — 계산기 요구와 100% 일치 |
| C2 해결 | active 시 grayscale→컬러 + 라벨 볼드 — opacity 40% 차이보다 훨씬 강한 신호, 색맹 사용자도 명도 대비로 식별 |
| 터치 타겟 | label 전체 클릭 영역(w-12/desktop:w-14), WCAG 2.5.8 24px+ 만족(ADR-0011 체계 내 원자) |
| 라벨 가시성 | 모바일 라벨 상시 노출이 TypeChip 기본값 — "선택이 핵심 과업"인 계산기 요구 충족 |

`TypeEffectivenessContext`(선택 상태·토글·리셋)는 그대로 재사용. 초기화는 그룹 밖 별도 `ButtonComponent`(m2).

### 질문 2 — 결과 표시: TypeMatchup 재사용 여부

**결정: TypeMatchup을 그대로 쓰지 않고, 시각 언어(`grade-*` 토큰·배지+dl 시맨틱)만 승계한 계산기 전용 컴포넌트(`TypeCalculatorResult`, 신규)로 재구성. TypeMatchup href 확장은 하지 않는다.**

| | TypeMatchup(상세) | 계산기 결과(D그룹) |
|---|---|---|
| 관점 | **방어**(이 포켓몬이 맞으면) | **공격**(내가 상대를 때리면) — 같은 5분류 라벨이지만 행동 지침 극성이 반대 |
| 상호작용 | 정적 표시 | **타입 클릭 → 도감 이동**(기존 기능 유지 필수) |
| 비중 | 병렬 섹션 중 하나 | 페이지 핵심 산출물 |

TypeMatchup에 href를 추가하면 상세 페이지에서는 항상 미사용 옵션으로 남아 컴포넌트 계약만 복잡해진다. **컴포넌트 재사용이 아니라 디자인 언어(토큰·패턴) 재사용**으로 처리 — 보류 트랙 "TypeMatchup 상성계산기 재사용"의 판정 결과다. 섹션 라벨은 계산기 전용("이런 타입을 쓰면 좋아요/조심해야 해요" 계열 유지, 약점/강점 라벨 금지 — 극성 오해 방지).

**배율 표기 형태 확정(2026-07-20, 시안 (a)/(b) 비교 후 사용자 결정): (b) 배율 텍스트형.** 배율은 배지가 아니라 크고 굵은 grade-* 색 텍스트(×4, 모바일 text-2xl·데스크톱 text-3xl급) + 좌측 고정 폭 컬럼 세로 정렬 + 행 좌측 grade 색 세로 보더(4px). 타입 칩만 배지 형태로 남아 "배지 = 타입" 단일 규칙로 혼동을 원천 차단한다(시안 피드백: 배율 배지와 타입 칩이 같은 규격이라 구분 불가).

**개정(2026-07-20, QA 라운드 2 — 사용자 재결정): 압축 표기(×4) 대신 구버전 설명 문장으로 최종 전환.** "4배의 데미지를 줄 수 있어요"처럼 문장이 초심자에게 자명하다. 문장이 길어 좌측 고정 폭 컬럼 대신 **문장 위·타입 칩 아래 세로 구조**로 재배치, grade 색은 문장 색+행 좌측 보더로 위험도 신호 유지. 조심 섹션 문구는 공격 관점으로 정합("0.5배의 데미지만 줄 수 있어요" — 구버전 "받아요"는 관점 혼재).

### 질문 3 — 18×18 상성표

**결정: 반응형 단일 표 하나 — 데스크톱은 전체 폭 수용(스크롤 불필요), 모바일은 가로 스크롤 + sticky 첫 행/열 + 셀 최소 폭(min-w-11=44px). 계산기 선택 타입과 표 하이라이트 연동(Provider 승격).**

1. C1 실증 — 324셀 매트릭스는 축소로 해결 불가. 매트릭스형 데이터는 가로 스크롤+고정 헤더가 표준 반응형 권고(카드 전환 불가한 데이터 형태 — MoveTable 선례와 데이터 성격이 다름).
2. 가로 스크롤 부담 완화: 카드형 경계(rounded border)로 "별도 스크롤 위젯"임을 형태로 신호 + 첫 열 sticky로 기준 유지.
3. **계산기 연동**: 선택 타입의 행/열 자동 하이라이트 — 구버전은 Provider가 계산기+결과만 감싸 연동 불가였던 구조를 바로잡는다(Provider를 뷰 최상위로 승격).
4. activePointer(2배만/0.5배만/0배만 보기) 유지 + 버튼 어포던스 보강(m4) + "단일 타입 기준" 캡션(M4).

### 질문 4 — 섹션 순서/IA

**결정: 계산기 → 결과 → 표 → 설명 순서 유지. `PageHeaderComponent` 신규 도입(구버전은 sr-only h1만).**
설명 섹션은 최하단이라 접이식 전환 불필요(ability "특성이란?"은 핵심 과업을 가로막는 위치였던 것과 상황이 다름).

### 질문 5 — URL 연동

**결정: 이번 트랙 미도입, 로컬 상태(Context) 유지. `revalidate` 제거.**
계산기의 가치는 즉석 인터랙션이지 조합별 랜딩이 아니다(조합 153가지의 SEO 수요 낮음). URL 동기화는 향후 최소 변경으로 추가 가능한 구조라 미도입이 확장을 막지 않는다.

### 질문 6 — 광고 슬롯

**결정: 동일 적용, 3종 제거**(DesktopTypeEffectivenessBanner·MobileTypeEffectivenessBanner·MobileTypeEffectivenessBottomBanner). 반응형 유닛 재도입은 별도 트랙.

## 8. 반응형 전략

- 계산기: `flex flex-wrap gap-2`(TypeChip 고정폭과 호환)
- 결과: `grid-cols-1 desktop:grid-cols-2 desktop:gap-8`(TypeMatchup 그리드 승계)
- 표: 모바일 `overflow-x-auto` + 셀 `min-w-11`(44px) + sticky 첫 행(top-0)/첫 열(left-0), 데스크톱 `w-full`(20칸×56px 안팎 수용)
- gutter `px-4`, 콘텐츠 `max-w-[1280px]`, 본문 `text-base`(ADR-0012)
- activePointer 토글 `min-h-8 desktop:min-h-9`(ADR-0011 슬림 계열)

## 9. 접근성

- 계산기: `role="group"` + aria-label(원자 TypeChip이 개별 라벨 보장)
- 결과: `aria-live="polite"` 범위는 h2(선택 요약)로 좁혀 소음 방지(§10-3)
- 결과 배지: Link + `aria-label="{타입명} 타입 포켓몬 도감 보기"` + focus-visible
- 표: table 시맨틱(scope) 유지, 스크롤 컨테이너 `tabindex="0"`+aria-label(W3C scrollable region 키보드 요구)
- 배율 셀: 색+텍스트 병기 이미 충족(유지)
- activePointer: `aria-pressed` 유지 + 시각 어포던스 보강

## 요약 — 핵심 결정 5가지

1. **타입 선택은 TypeChip DS(mode='multi') 재사용** — 도감 리스트와 동일 요구, 선택 대비 약함(C2) 근본 해결
2. **결과는 TypeMatchup 컴포넌트 재사용 ✗, 디자인 언어(grade-* 토큰·패턴) 승계한 전용 컴포넌트 신설** — 공격/방어 극성 반대·클릭형 링크 요구 (보류 트랙 판정 완료)
3. **표는 반응형 단일**: 데스크톱 전체 폭, 모바일 가로 스크롤+sticky 첫행/열+min-w-11. **계산기 선택과 하이라이트 연동**(Provider 뷰 최상위 승격)
4. **섹션 순서 유지 + PageHeader 신규 도입**, 광고 3종 제거
5. **URL 연동 미도입**(로컬 상태 유지), revalidate 제거, 크롬만 UA분기(A~C 패턴)
