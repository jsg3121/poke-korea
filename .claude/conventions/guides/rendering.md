# 렌더링 및 데이터 연동 가이드

Next.js App Router의 렌더링 전략과 캐시 정책을 규정한다.

관련 문서 — 폴더 배치(`_fetch`/`_metadata`)와 GraphQL 파일 관리는 `structure.md`, 계층별 책임은 `coding.md`.

---

## 라우트 구조 규칙

라우트 목록은 문서에 두지 않는다 — `find src/app -name "page.tsx"`로 언제든 확인할 수 있고, 수동 목록은 라우트가 늘 때마다 어긋난다.

여기서는 **경로를 설계하는 규칙**만 규정한다.

### 폼 라우트는 Path로 표현한다

포켓몬의 폼(메가진화·리전폼·폼체인지·거다이맥스)은 쿼리 파라미터가 아니라 경로 세그먼트로 구분한다.

```text
/detail/6/mega          # 메가리자몽 (첫 번째)
/detail/6/mega/1        # 메가리자몽 Y
/detail/6/region        # 리전폼
```

> **Why:** 쿼리 파라미터(`?activeType=mega`)는 검색엔진이 같은 페이지의 변형으로 취급해 색인에서 누락되기 쉽다. 경로로 나누면 각 폼이 독립 URL을 가져 개별 색인·공유가 가능하다. 구버전 쿼리 URL은 `next.config.js`의 `redirects()`가 301로 넘긴다.

### 인덱스는 옵셔널 캐치올로 받는다

폼이 여러 개인 경우 `[[...index]]`를 쓴다. 첫 번째 폼은 인덱스 없이(`/mega`), 그 이후는 번호로(`/mega/1`) 접근한다.

```text
app/detail/[pokemonId]/(form)/mega/[[...index]]/page.tsx
```

> **Why 옵셔널인가:** `[...index]`(필수)로 두면 `/detail/6/mega`가 404가 되어 첫 번째 폼에 접근할 수 없다. 옵셔널이면 인덱스 유무를 한 라우트가 모두 처리한다.

### 라우트 그룹으로 URL에 영향 없이 묶는다

`(form)`처럼 괄호로 감싼 폴더는 URL에 포함되지 않는다. 같은 레이아웃·캐시 정책을 공유하는 라우트를 묶는 데 쓴다.

## 캐시 정책

두 개의 층이 함께 동작한다. **혼동하지 말 것** — `revalidate`는 서버가 페이지를 다시 만드는 주기이고, `Cache-Control`은 브라우저·CDN이 응답을 보관하는 기간이다.

### ISR (`revalidate`)

| 값               | 용도                                            |
| ---------------- | ----------------------------------------------- |
| `31536000` (1년) | 도감·기술·특성 상세 — 게임 데이터라 사실상 불변 |
| `86400` (1일)    | 챔피언스 등 주기적으로 갱신되는 메타 데이터     |

> **Why 1년인가:** 포켓몬 종족값·타입·기술 데이터는 게임 버전이 올라가지 않는 한 바뀌지 않는다. 무기한으로 두지 않는 이유는 백엔드 데이터 정정이 반영될 통로를 남기기 위해서다.

### `Cache-Control` (`next.config.js`의 `headers()`)

| 경로  | 값                              | 의미                                   |
| ----- | ------------------------------- | -------------------------------------- |
| `/`   | `max-age=0, s-maxage=86400`     | 브라우저는 매번 재검증, CDN은 1일 보관 |
| 그 외 | `max-age=10800, s-maxage=86400` | 브라우저 3시간, CDN 1일                |

> **Why 홈만 `max-age=0`인가:** 홈은 오늘의 포켓몬·퀴즈처럼 자주 바뀌는 콘텐츠를 담아, 브라우저가 3시간 묵은 화면을 보여주면 안 된다. CDN 캐시는 유지해 원본 부하는 막는다.

## `next.config.js` 주요 설정

| 항목                          | 값         | 목적                                                     |
| ----------------------------- | ---------- | -------------------------------------------------------- |
| `reactStrictMode`             | `true`     | 개발 중 부작용 이중 호출로 문제 조기 발견                |
| `compiler.removeConsole`      | 프로덕션만 | 번들에서 `console.*` 제거                                |
| `poweredByHeader`             | `false`    | `X-Powered-By` 노출 차단                                 |
| `productionBrowserSourceMaps` | `false`    | 소스맵 비공개                                            |
| `redirects()`                 | —          | 레거시 쿼리 URL → Path URL 301                           |
| `headers()`                   | —          | 경로별 `Cache-Control`                                   |
| `webpack()`                   | —          | SVG → React 컴포넌트(`@svgr/webpack`), 프로덕션 CSS 분리 |

## 데이터 패칭

### 서버에서 가져오고 클라이언트로 흘린다

`page.tsx`가 Apollo로 데이터를 가져와 `initialApolloState`로 하이드레이션한다. 클라이언트에서 같은 쿼리를 다시 쏘지 않는다([ADR-0014](../../decisions/records/ADR-0014-apollo-ssr-cache-hydration.md)).

### 패칭 위치

라우트가 여러 개면 `_fetch/`로 분리하고, **응답 가공까지 함께** 옮긴다. 배치 규칙은 `structure.md` 참조.

### 스키마 변경 절차

GraphQL 원본을 수정한 뒤 `npm run codegen`을 실행한다. 생성물은 직접 수정하지 않는다.

```bash
npm run codegen   # localhost:4000/graphql 서버가 떠 있어야 한다
```

## 검증

라우팅·메타데이터를 바꾼 뒤에는 **실제 페이지를 요청해 확인한다.** 타입 검사·린트·빌드를 모두 통과하고도 런타임 500이 나는 경우가 있다.

```bash
curl -s -o /dev/null -w '%{http_code}' http://localhost:3000/detail/6/mega
```

> **주의:** 개발 서버가 떠 있는 상태에서 `npm run build`를 실행하지 않는다. `.next` 디렉토리를 공유해 실행 중인 서버가 죽는다.
