## 1. 이슈 개요 (TL;DR)

2026-10-04부터 네이버 서치어드바이저 노출이 하루 약 7.8만 건에서 2.5만 건(10-06)으로 급감했다. 클릭도 함께 줄었고, GA4 일 사용자와 애드센스 수익도 약 30% 감소했다.

### 최종 진단 (현재까지)

**네이버가 서로 다른 상세 페이지들을 `/detail/1` 하나로 대표 색인하고 있다.** 사이트는 페이지마다 고유한 canonical·메타·JSON-LD·본문을 정상으로 제공하고 있어, 네이버 측 중복 판정 이상으로 판단한다.

```
서치어드바이저 색인 확인 (2026-10-06)
  요청 URL : https://poke-korea.com/detail/768   (150, 512도 동일)
  indexedUrl: https://poke-korea.com/detail/1
  cnUrl     : null
  jsonld    : {}
  statusCode: 200 / crawlResult: SUCCESS / redirectUrl: ""
```

> `indexedUrl`을 "네이버가 고른 대표 URL"로 해석했다. 이 필드의 의미를 정의한 네이버 공식 문서는 찾지 못했으며, 필드명과 상황으로 추론한 것이다.

## 4. 가설 검증 과정

### 4.1 H-1 배포 코드 — 배제

09-30 머지(#238) 전후로 SEO 관련 파일만 골라, 주석 줄을 뺀 실제 코드 변경을 비교했다.

- 메타데이터·sitemap·JSON-LD 생성기: import 경로 변경(`~/module` → `~/modules`)만 있음
- `getRobotsConfig()`(index/follow): 변경 없음
- 페이지: 헤더·푸터·`<main>`을 각 page에서 `layout.tsx`로 올린 구조 이동. `Detail.view.tsx`는 이름·주석만 변경
- 1.61.1: 클라이언트 검색 UI·카드 표시 수정
- GitHub에서도 브랜치는 `main` 하나, 최신 커밋은 3236a31(10-01). 그 뒤 배포 없음

### 4.2 H-2 CloudFront 함수 — 배제

**403 로그 (09-25 ~ 10-06 쿼리, 870건)**

| 항목 | 결과 |
| --- | --- |
| 응답 | 전부 403 (FunctionGeneratedResponse 869, Error 1: zgrab 스캐너) |
| 국가 | SG 759, CN 89, HK 21, DE 1, **KR 0** |
| UA | Bytespider 564, 브라우저 위장 306 |
| Yeti·Naver·Google·Bing·Daum | **0건** |
| 날짜별 | 09-27 96, 09-28 235, 09-29 210 → 10-01 이후 하루 5~80건 |

**함수 코드 검토**

- `request.uri`·쿼리를 바꾸지 않고 `x-device-type` 헤더만 추가 → 다른 URL의 HTML이 캐시될 경로 없음
- 차단 CIDR 계산을 재현해 판정: `110.93.150.98`(네이버) 통과, `43.172.194.70`·`43.173.179.37` 차단
- 네이버 수집 IP `110.93.150.98` 역방향 DNS: `crawl.110-93-150-98.web.naver.com`, 정방향 재조회 일치 → 실제 네이버 크롤러

**GA4 교차 확인**

- 서치어드바이저 클릭은 사용자가 사이트에 오기 전 네이버가 집계한다. 함수가 사용자를 막았다면 네이버 클릭은 그대로이고 GA4만 줄어야 하지만, 실제로는 네이버 클릭부터 줄었다
- Google·Bing 유입은 그대로 → 사이트 접속 자체는 정상
- 차단 건수(하루 수십 건)로는 하루 600명 감소를 설명할 수 없다
- 함수 적용(09-27)과 하락 시작(10-04) 사이 09-29 ~ 10-03은 평소 수준

참고: 09-28 ~ 09-30에 403을 받은 CN `Android 5.0` UA 요청은 현재 함수 코드로는 차단되지 않는다. 그 사이 함수 버전이 바뀐 것으로 보이며, 이번 이슈와는 무관하다.

### 4.3 H-3 robots.txt — 배제

- Yeti는 전용 그룹이 없어 `User-Agent: *` 그룹을 따른다. 이 그룹의 변경은 존재하지 않던 경로 `/image` 차단 제거뿐이다 → Yeti에게는 오히려 더 열림
- 운영 중인 robots.txt를 `urllib.robotparser`로 판정: Yeti·Googlebot·Daum은 `/`, `/detail/25`, `/moves/1`, `/sitemap.xml`, `/assets/type/*` 모두 허용. GPTBot·Bytespider는 모두 차단
- 배포 다음 날(10-01 ~ 10-02) 수집 완료가 기간 최고치 → 새 robots.txt를 받은 뒤에도 수집 정상

### 4.4 H-4 네이버 전체 개편 — 배제

- 운영자의 회사 사이트 서치어드바이저 지표는 변동 없음
- "피카츄 기술", "리자몽 진화" 검색 시 나무위키·팬덤 위키는 정상 노출
- 단, 포켓몬·게임 분야에만 적용된 변화 가능성은 회사 지표만으로는 배제되지 않는다

### 4.5 H-5 캐시 키의 쿼리 문자열 — 배제

CloudFront 캐시 정책 `poke-korea-cloudfront` (마지막 수정 2026-08-06):

| 항목 | 설정 |
| --- | --- |
| 헤더 | `x-device-type` (`X-Device-Type`도 등록, 대소문자 구분 없어 같은 키) |
| 쿠키 | 없음 |
| 쿼리 문자열 | `utm_term`, `fbclid`, `gclid`, `utm_campaign`, `utm_medium`, `_ga`, `utm_source`, `utm_content`을 **제외한 모든 쿼리 포함** |
| TTL | 최소 1 / 기본 86400 / 최대 31536000 |

쿼리는 캐시 키에 포함되고, 마지막 수정이 08-06이라 이번 시점과 무관하다.

### 4.6 H-6 Yeti가 받는 HTML — 배제

- Next.js 15.5.18의 `HTML_LIMITED_BOT_UA_RE`(`dist/shared/lib/router/utils/html-bots.js`)에 `Yeti`가 포함 → 서버가 Yeti에게 직접 응답할 때는 메타데이터가 `<head>`에 들어간다
- 브라우저 UA로 캐시를 먼저 채운 뒤 Yeti UA로 요청(`x-cache: Hit`)해도 결과가 같았다

| 페이지 | x-cache | `<head>` 안 canonical | `<head>` 안 title | JSON-LD |
| --- | --- | --- | --- | --- |
| /detail/1 | Hit | 1 | 1 | 2 |
| /detail/768 | Hit | 1 | 1 | 2 |

Yeti UA로 직접 받은 HTML (`Mozilla/5.0 (compatible; Yeti/1.1; +https://naver.me/spd)`):

| URL | 응답 | `<title>` | canonical |
| --- | --- | --- | --- |
| /detail/1 | 200 | No. 1 이상해씨 - 포케 코리아 | https://poke-korea.com/detail/1 |
| /detail/150 | 200 | No. 150 뮤츠 - 포케 코리아 | https://poke-korea.com/detail/150 |
| /detail/512 | 200 | No. 512 야나키 - 포케 코리아 | https://poke-korea.com/detail/512 |
| /detail/768 | 200 | No. 768 갑주무사 - 포케 코리아 | https://poke-korea.com/detail/768 |

- `meta description`, `og:url`, `robots`(index, follow, max-image-preview:large)도 각 페이지 고유 값
- JSON-LD(WebPage)의 `url`, `breadcrumb`, `mainEntity`도 해당 페이지 자신을 가리킨다
- HTML 전체에서 다른 상세 페이지 번호를 가리키는 절대 URL은 없다

### 4.7 H-7 본문 유사도 — 배제

**방법**

1. Yeti UA로 받은 HTML의 `<body>`에서 `script`·`style`·`noscript`·`template`와 `hidden` 속성 요소를 제외하고 텍스트 노드만 추출
2. 공백 기준으로 단어를 나눠 5단어 묶음(5-gram) 집합을 만듦
3. 두 페이지 집합의 Jaccard 유사도 = 교집합 크기 / 합집합 크기

**결과**

| 페이지 | 화면 텍스트 글자 수 | 단어 수 | HTML 크기 | 스크립트 비중 |
| --- | --- | --- | --- | --- |
| /detail/1 | 1,400 | 378 | 124,137B | 39% |
| /detail/150 | 1,541 | 399 | 132,164B | 45% |
| /detail/512 | 1,352 | 364 | 124,619B | 41% |
| /detail/768 | 1,332 | 358 | 128,861B | 42% |

| 비교 | 5-gram Jaccard 유사도 |
| --- | --- |
| /detail/1 vs /detail/150 | 0.14 |
| /detail/1 vs /detail/512 | 0.24 |
| /detail/1 vs /detail/768 | 0.20 |

- 겹치는 부분은 대부분 공통 틀: 상단 메뉴(포켓몬 도감·기술 도감·특성 도감 등), 퀴즈 안내 문구, 저작권 푸터
- 고유 부분은 서버 렌더링된 HTML에 그대로 있다. 예: 768의 종족값 530, 특성 위기회피, 습득 기술(만나자마자·칼춤·파도타기 등), 진화(꼬시레 → 갑주무사, 레벨 30)
- 상세 컨테이너에 클라이언트 전용 렌더링(`ssr: false`, 마운트 확인 등)은 없다

→ 중복 문서로 판정될 수준이 아니다.

### 7.1 진행 중

- 서치어드바이저 고객센터에 문의 (1,000자 이내 메시지, 색인 확인 JSON·리포트 캡처 첨부)
- 문의 근거: 사이트 응답과 네이버 색인 결과의 불일치, Google 유입 −4% 대비 네이버 유입 −58%

### 7.2 유지할 것

- **URL·canonical 구조는 바꾸지 않는다.** 원인이 네이버 쪽이라면 구조 변경은 재평가를 늦출 수 있다

### 7.3 추적

- 며칠 간격으로 `/detail/768`, `/detail/150`, `/detail/512`의 `indexedUrl` 재확인
- GA4 네이버 유입 추이 확인:

```bash
node .claude/analyzer/scripts/ga4.js \
  --dim=date,sessionSource \
  --met=activeUsers,sessions \
  --start=2026-09-29 --end=<오늘> --limit=300
```

- 주요 상세 페이지에 "웹 페이지 수집 요청" 후 `indexedUrl` 변화 관찰

## 9. 학습 포인트

- **수집 지표를 먼저 본다.** 수집 완료가 정상이고 제한이 0이면 접근 차단(robots·CDN)은 원인이 아니다. 노출 급감 초기에 이를 확인했다면 CloudFront 함수 의심을 더 빨리 접을 수 있었다
- **유입 경로별로 쪼갠다.** 특정 검색엔진만 줄었는지 전체가 줄었는지가 사이트 문제와 검색엔진 문제를 가르는 가장 빠른 기준이다
- **색인 확인 도구의 `indexedUrl`을 확인한다.** 요청 URL과 다르면 중복 판정 문제다
- **HTML 검사 스크립트는 한 줄짜리 HTML을 전제로 작성한다.** 줄 단위 도구(`awk` 등)는 Next.js 출력에서 오판한다
