# specs/

기획서·계획서·현황 문서를 관리하는 폴더입니다.

성격이 다른 문서가 섞이지 않도록 하위 폴더로 나눕니다. 배치 규칙은 [`../conventions/guides/structure.md`](../conventions/guides/structure.md)가 권위 원본입니다.

## 하위 구조

| 폴더         | 담는 것                      | 특징                                      |
| ------------ | ---------------------------- | ----------------------------------------- |
| `service/`   | 서비스 현황·지표·타겟·경쟁사 | **지속 갱신** — 최신 상태를 유지한다      |
| `features/`  | 기능별 기획서(SPEC)          | 기능 단위, 완료 후에도 설계 근거로 남는다 |
| `plans/`     | 실행 계획서                  | 작업 단위, 종결되면 종결 표시를 남긴다    |
| `incidents/` | 장애·사고 기록               | 재발 방지 근거                            |

> **Why 나누는가:** 분류 없이 쌓으면 "지금도 유효한 현황"과 "이미 끝난 일회성 계획"이 섞여, 어느 것을 믿어야 할지 알 수 없다.

## 문서 성격 구분

**`service/`** — 이 서비스가 지금 어떤 상태인가. 지표가 바뀌면 문서도 갱신한다.

**`features/`** — 이 기능을 왜, 어떻게 만들기로 했는가. 구현이 끝나도 판단 근거로 남는다.

**`plans/`** — 무엇을 어떤 순서로 할 것인가. 완료되면 문서 상단에 종결 표시를 남기고 보존한다(삭제하지 않는다 — 왜 그 순서였는지가 이후 판단의 근거가 된다).

## 작성 규칙

- 기획서는 `product-planner` 에이전트가 담당한다. 정의는 [`../agents/product-planner.md`](../agents/product-planner.md).
- 기술적 의사결정이 포함되면 ADR로 분리한다 — 규칙은 [`../decisions/index.md`](../decisions/index.md).
- 백엔드 등 **다른 저장소가 대상인 문서는 두지 않는다.** 이 폴더는 이 저장소의 작업을 다룬다.
