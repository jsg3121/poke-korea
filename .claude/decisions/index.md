# decisions/

구조 결정의 **현재 상태**와 **결정을 기록하는 방법**을 관리하는 폴더다. 이 문서는 기록 방법과 지침 변경 절차의 권위 원본이다.

## 구성

| 파일                                | 역할                                                                   |
| ----------------------------------- | ---------------------------------------------------------------------- |
| [`architecture.md`](architecture.md) | 지금 유효한 구조 결정 — **구조 결정의 권위 원본**                     |
| `index.md`                          | 결정 기록 방법과 지침 변경 절차 (이 문서)                              |
| [`records/`](records/index.md)      | 2026-11-23까지 작성한 ADR 보관본. 새로 쓰거나 고치지 않는다            |

## 구조 결정을 기록하는 방법

**구조 결정**은 코드나 서비스 구조에 관한 결정이다 — 아키텍처, 데이터 흐름, API·쿼리 계약, 렌더링·캐시 전략, 상태 관리, 폴더 구조, 핵심 의존성 도입·교체.

1. 그 작업 PR에서 `architecture.md`의 해당 절을 **현재 상태로** 고친다. 이전 상태나 변경 경위는 문서에 남기지 않는다.
2. 검토한 대안, 고른 이유, 기각 사유, 근거 링크는 **PR 본문의 "검토한 대안" 섹션**에 쓴다(`create-pr`의 PR 템플릿).
3. 코드 주석·SPEC·가이드·에이전트 문서에는 결정 내용을 다시 적지 않고 `architecture.md`의 절을 링크한다. 세부 작성 규칙이 가이드에 있으면 `architecture.md`가 그 가이드를 가리킨다.

어떤 절이 언제 왜 바뀌었는지는 `git log -p -- .claude/decisions/architecture.md`로 해당 PR을 찾아 본문을 읽는다.

구조 결정이 아닌 것(기능 기획, 지표·KPI, 운영 방침, 이름 규칙 같은 코딩 규칙 세부)은 해당 SPEC이나 가이드에 적고, 검토한 대안은 마찬가지로 PR 본문에 남긴다.

> **Why (2026-11-23):** 이전에는 결정마다 ADR을 쓰고 그 ADR이 현재 규칙의 원본 역할을 했다. ADR이 26개로 늘자 결정 하나가 바뀔 때마다 ADR과 그 내용을 옮겨 적은 가이드·SPEC·에이전트 문서를 함께 고쳐야 했고, 하나라도 빠지면 다음 작업이 낡은 규칙을 따랐다. 현재 상태는 한 문서에만 두고, 시점의 근거는 어차피 남는 PR·커밋에 두어 동기화 대상을 없앤다. 운영 규칙의 변경이라 이 절에 기록한다.

### 대안을 정리하는 시점

구조 결정에서 **해결 후보 2개 이상 비교, 트레이드오프 판단, 검토 후 기각** 중 하나가 나오면 논의가 끝나기를 기다리지 말고 그 자리에서 후보·고른 이유·기각 사유를 정리해 사용자에게 보여준다. 이 정리가 PR 본문의 "검토한 대안"이 되고, `architecture.md`를 고쳐야 하는 결정인지도 함께 알린다.

> **Why:** 트레이드오프 근거는 대화 중에 가장 선명하지만 코드 diff에는 남지 않는다. 특히 기각된 대안은 흔적이 없어, 나중에 같은 검토를 반복하거나 이미 버린 방안을 다시 꺼내게 된다.

대상이 아닌 경우: 원인이 명확하고 해법이 하나인 버그 수정, 스타일·문구 조정, `architecture.md`에 있는 결정의 반복 적용.

## 지침 변경 관리

진행 중인 작업이 기존 지침·규칙과 어긋날 때 따른다.

1. **현재 규칙 확인**: `architecture.md`와 해당 가이드에서 지금 규칙을 확인한다.
2. **충돌 지점 명시**: 기존 규칙의 어느 부분이 현재 상황과 맞지 않는지 구체적으로 짚는다.
3. **합의**: 왜 바꿔야 하는지 근거를 제시하고 사용자와 합의한다.
4. **원본 한 곳만 고친다**: 규칙은 한 문서에만 있어야 한다. 다른 문서가 같은 내용을 다시 적고 있으면 고치지 말고 원본 링크로 바꾼다.
5. **이유 기록**: 변경 이유는 PR 본문에 남긴다. 운영 규칙처럼 문서 안에서 이유를 알아야 하는 경우에만 그 절에 날짜와 함께 적는다.

## 보관된 ADR

`records/ADR-*.md`는 결정 당시의 맥락·근거·대안을 담은 기록이다.

- **고치지 않는다.** 공개 changelog가 이 파일들을 링크하므로 삭제하거나 이동하지도 않는다.
- 현재 규칙은 `architecture.md`에서 찾고, 결정의 깊은 근거가 필요할 때만 해당 ADR을 읽는다.
- ADR 안의 상태(`승인`·`대체됨`·`폐기`·`제안`)는 보관 시점 그대로다. 현재 유효 여부는 `architecture.md`가 판단 기준이다.
