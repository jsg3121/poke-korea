# ADR-0010: 원자 컴포넌트 우선 DS 구축 (atom → 조립 → 페이지)

- **상태**: 승인
- **날짜**: 2026-06-24
- **담당**: jsg3121 + Claude

## 맥락

[mobile-redesign-plan.md](../../specs/mobile-redesign-plan.md)의 4단계 전략은
**"1단계는 토큰/Foundations만, 컴포넌트는 페이지를 그려봐야 뭐가 필요한지 아니까
2단계에서 페이지 작업과 함께 만든다"** 는 가정 위에 있었다(기획서 4.1, 4.2).

홈 Phase B(컨테이너 조립, [PR #173](https://github.com/jsg3121/poke-korea/pull/173))를
진행하면서 이 가정의 비효율이 드러났다. 컨테이너를 조립할 때 **디자인 시스템화되지
않은 최소 단위(CTA 버튼, 링크 등)** 를 만나면, DS가 없으므로:

1. 인라인으로 임시 구현하고 (예: HomeChampions의 "챔피언스 전체 도감 보기" CTA를
   긴 className으로 인라인 작성)
2. 나중에 그 원자를 DS로 만들면 **다시 찾아가 교체**한다.

이 "임시 구현 → 재작업" 이중 작업이 페이지마다 반복된다. 원자 컴포넌트(버튼/링크/
라디오/토글 등)는 **페이지를 그려보지 않아도 필요성과 형태가 자명**한데, 기존 전략이
이들을 페이지 작업까지 미루기 때문에 발생하는 낭비다.

## 결정

DS 구축 순서를 **원자(atom) 우선**으로 바꾼다. Atomic Design 계층(atoms → molecules
→ organisms)의 정석 순서를 따른다.

1. **원자 컴포넌트를 먼저 일괄 DS화** — 코드베이스에서 실제 쓰이는 최소 단위(CTA 버튼,
   링크, 인풋, 라디오, 토글, 체크박스, 칩 등)를 전수 조사해 목록화하고, 토큰 기반 신규
   DS 컴포넌트로 일괄 구축한다(각 Storybook story 포함).
2. **그다음 분자/컨테이너 조립** — 원자가 이미 DS로 존재하므로 조립 시 임시 구현이 없다.
3. **페이지별 UI 재구성** — atom·molecule이 모두 DS라 페이지 작업이 순수 조립이 된다.

기존 "1단계 = Foundations만, 컴포넌트는 2단계에서"는 **"1단계 = Foundations + 원자
컴포넌트, 2단계 = 조립/페이지"** 로 개정한다.

## 근거

- **이중 작업 제거**: 원자가 미리 있으면 상위 조립에서 인라인 임시 구현·재작업이 사라진다.
  실제 Phase B에서 CTA 인라인 → 재작업 예정 케이스가 발생했다(검증된 비효율).
- **Atomic Design 정석**: atoms를 먼저 만들고 그 위에 molecule/organism을 쌓는 것이
  디자인 시스템의 표준 빌드 순서다. 원자는 페이지 맥락 없이도 형태가 자명하다.
  ([Atomic Design — Brad Frost](https://bradfrost.com/blog/post/atomic-web-design/))
- **기존 "페이지를 그려봐야 안다" 가정의 적용 범위 축소**: 이 가정은 *복합/도메인
  컴포넌트*(카드 변형, 페이지 특화 패턴)에는 여전히 유효하다. 그러나 *원자*에는
  과잉이었다 — 버튼·링크·인풋이 필요하다는 건 페이지를 안 그려봐도 안다.
- **"안 쓰는 게 쌓인다" 리스크 관리**: 기존 Why(기획서 4.2)의 우려는 유효하므로,
  원자는 **상상이 아니라 코드베이스에 실제 사용처가 있는 것만** 전수 조사해 만든다
  (추측 기반 선제작 금지).

## 대안

| 대안 | 장점 | 단점 | 불채택 사유 |
|------|------|------|-------------|
| 페이지 단위 진행 유지(현행) | 실제 필요한 것만 그때그때 | 원자마다 임시 구현→재작업 이중 비용 | 검증된 비효율 |
| 원자 우선 일괄 (채택) | 이중 작업 제거, Atomic 정석 | 초기 원자 조사·구축 비용 선투입 | 사용처 있는 것만 만들어 낭비 방지 |
| 모든 컴포넌트 선제작 | 완전성 | 안 쓰는 컴포넌트 양산, 비대화 | 기획서 4.2 Why 위반 |

## 결과

- 다음 작업은 **전체 원자 컴포넌트 전수 조사 → 일괄 DS 구축**이다(페이지 작업 일시 보류).
- `mobile-redesign-plan.md`의 1·2단계 서술을 개정한다(원자를 1단계로 편입).
- Phase B에서 인라인으로 남긴 CTA 등은, 원자 DS(버튼/링크) 구축 후 교체한다.
- 원자는 코드베이스 실사용처 기반으로만 만든다(추측 선제작 금지).
