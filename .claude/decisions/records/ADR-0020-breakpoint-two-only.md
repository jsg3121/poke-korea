# ADR-0020: 브레이크포인트를 2종으로 고정한다

- **상태**: 승인
- **날짜**: 2026-09-17
- **담당**: jsg3121 + Claude

## 맥락

`styling.md`를 점검하면서 문서와 설정이 어긋난 것을 발견했다.

문서는 브레이크포인트를 `mobile`(max 768px)·`desktop`(min 769px) 2종으로 규정하는데, `tailwind.config.js`에는 4종이 정의돼 있다.

| 이름          | 조건               | 문서 |
| ------------- | ------------------ | ---- |
| `mobile`      | `max-width: 768px` | ✅   |
| `desktop`     | `min-width: 769px` | ✅   |
| `desktop-970` | `max-width: 970px` | ❌   |
| `desktop-639` | `max-width: 639px` | ❌   |

추가된 2종에는 두 가지 문제가 있다.

**1. 이름이 실제 동작과 반대로 읽힌다.** `desktop-970`은 이름에 `desktop`이 있지만 `max-width`로 정의돼 **모바일 구간까지 포함**한다. 데스크톱 전용으로 오해하고 쓰면 모바일 스타일까지 덮어쓴다.

**2. 중첩 변형이 동작하지 않는다.** "데스크톱이면서 970px 이하"를 표현하려면 `desktop:desktop-970:` 형태가 필요한데, Tailwind는 이 조합에 대해 CSS 규칙을 생성하지 않는다. 즉 두 브레이크포인트가 서로를 좁힐 수 없어, 구간을 쪼개도 원하는 영역을 표현하지 못한다.

**두 브레이크포인트 모두 클래스로 사용된 곳이 없다.** `desktop-970`의 유일한 등장은 `TypeQuickLinks.container.tsx`의 주석이며, 그 내용은 "이 브레이크포인트를 쓰려 했으나 위 두 문제 때문에 포기하고 6열로 통일했다"는 기록이다.

## 결정

**브레이크포인트는 `mobile`·`desktop` 2종만 유지하고, `desktop-970`·`desktop-639`를 제거한다.**

`tailwind.config.js`의 `screens`에 브레이크포인트를 추가하지 않는다. 중간 구간이 필요해 보이면 레이아웃을 먼저 조정한다 — 열 수나 고정 폭을 바꿔 한 구간이 전 폭을 커버하게 만든다.

## 근거

**구간을 쪼개는 방식은 이 프로젝트에서 작동하지 않는다.** Tailwind가 중첩 변형 규칙을 만들지 않으므로, `max-width` 브레이크포인트를 추가해도 "데스크톱 안의 좁은 구간"을 표현할 수 없다. 표현할 수 있는 것은 "전 구간에서 970px 이하"뿐인데, 이는 모바일 스타일을 덮어써 모바일 퍼스트 원칙과 충돌한다.

**레이아웃 조정이 더 단순하고 검증하기 쉽다.** 타입 칩 그리드에서 9열이 970px 이하에서 깨지는 문제는, 구간을 나누는 대신 6열로 줄여 해결했다. 6열이면 769px에서도 글자 여유가 남아 전 구간에서 안전하다. 구간별로 다른 열 수를 주면 경계마다 실기기 확인이 필요하지만, 한 값으로 통일하면 최소 폭 하나만 확인하면 된다.

**쓰지 않는 설정은 판단 비용을 만든다.** 사용처가 없는 브레이크포인트가 config에 남아 있으면, 다음 사람이 "이걸 써도 되나"를 매번 판단해야 한다. 특히 이름이 오해를 부르는 경우 잘못 쓸 위험이 크다.

## 대안

| 대안                             | 장점                   | 단점                                     | 불채택 사유                                     |
| -------------------------------- | ---------------------- | ---------------------------------------- | ----------------------------------------------- |
| **문서에 추가하고 함정을 경고**  | 설정 변경 없음         | 쓰지 않는 규칙을 문서가 계속 설명해야 함 | 사용처가 0이라 규정할 대상이 없다               |
| **이름을 `narrow-970`으로 변경** | `max-width`임이 드러남 | 중첩 변형 문제는 그대로 남음             | 이름을 고쳐도 쓸 수 없는 건 마찬가지다          |
| **`desktop-639`만 제거**         | 변경 최소              | `desktop-970`의 함정이 남음              | 둘 다 사용처가 없어 함께 제거하는 편이 일관된다 |

## 결과

- `styling.md`에 "브레이크포인트를 늘리지 않는다" 절 추가.
- 후속 작업(설정 변경):
  - `tailwind.config.js`의 `screens`에서 `desktop-970`·`desktop-639` 제거
  - `TypeQuickLinks.container.tsx`의 주석에서 `desktop-970` 언급 정리 — 결정 내용(6열 통일)만 남기고 폐기된 브레이크포인트 이름은 뺀다
- `content` 경로는 폴더 복수형 변경([ADR-0016](./ADR-0016-folder-structure-by-domain-usage.md)) 시 함께 갱신한다.
