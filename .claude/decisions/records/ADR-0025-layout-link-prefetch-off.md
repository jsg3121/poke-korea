# ADR-0025: 링크 prefetch 범위 조정 — 메뉴·타입 링크는 끄고, 포켓몬 카드는 의도 기반

- **상태**: 승인
- **날짜**: 2026-11-02 (2026-11-03 개정)
- **담당**: jsg3121, Claude

## 맥락

2026년 7월부터 CloudFront 요금이 늘었다. 5~6월에는 월 $1~2였는데 7월 $8.8, 8월 $14.4, 9월 $13.8, 10월 $19.0이 됐다(10월은 api 도메인의 CloudFront 경유분 $6.3 포함, 이 부분은 11월 2일 ALB 직행으로 되돌렸다). 비용은 거의 전부 **요청 수 과금**이고, 데이터 전송 비용은 월 $0.4 수준이다.

`poke-korea.com` 배포의 액세스 로그(2026-08-07, 2026-10-28 하루치)를 분석한 결과는 다음과 같다.

| 지표                                | 값                                                  |
| ----------------------------------- | --------------------------------------------------- |
| 전체 요청 중 RSC(`?_rsc=`) 요청     | 약 70%                                              |
| 페이지(HTML) 조회 1회당 RSC 요청    | 약 8.4건                                            |
| 오리진(EC2)까지 간 요청 중 RSC 비율 | 78%                                                 |
| 계정 전체 월 요청 수 (10월)         | 약 1,630만 건 (CloudFront 무료 한도: 월 1,000만 건) |

RSC 요청은 Next.js `<Link>`의 기본 prefetch가 만든다. Next.js 15는 화면에 들어온 링크를 미리 받아 두고, 정적 경로(ISR)는 경로 전체를 prefetch한다.

### RSC 요청의 목적지 (2026-10-28, 전체 요청 439,967건)

| 목적지                                   | RSC 요청 | 전체 요청 대비 | 실제 HTML 조회 | 주 발생원                                                                         |
| ---------------------------------------- | -------- | -------------- | -------------- | --------------------------------------------------------------------------------- |
| `/detail/{n}` (포켓몬 상세)              | 135,734  | 31%            | 8,471          | 포켓몬 카드(`PokemonCardShell`) — 도감 목록, 기술·특성·타입 상세, 챔피언스, 홈 |
| `/moves/*`                               | 39,625   | 9%             | 15,236         | 기술 목록 카드, 상세 페이지의 기술 링크                                           |
| `/champions/*`                           | 24,944   | 6%             | 3,110          | 챔피언스 카드·탭                                                                  |
| `/type-effectiveness/{type}`             | 19,904   | 5%             | 148            | 상성 표, 빠른 링크, 설명 본문 링크, 타입 상세 하단 목록                           |
| 메뉴 목적지 7곳(`/`, `/list`, `/moves` 등) | 약 27,600 | 약 6%         | —              | 탭바·헤더 메뉴와 일부 본문 링크                                                   |

## 결정

링크의 성격에 따라 prefetch를 세 가지로 나눠 적용한다.

**1. 공통 레이아웃 메뉴: prefetch를 끈다.** (1.62.3)

- `MobileTabBar.component.tsx`(링크 7개), `HeaderNav.container.tsx`(메뉴 7개 + 챔피언스 드롭다운 4개)의 모든 `<Link>`에 `prefetch={false}`를 적용한다.

**2. 포켓몬 카드: 사용자 의도가 보일 때만 prefetch한다.** (1.62.4)

- `PokemonCardShell.component.tsx`의 `<Link>`에 `prefetch={false}`를 적용하고, `onTouchStart`·`onMouseEnter`·`onFocus`에서 `router.prefetch(href)`를 호출한다.
- 이 컴포넌트를 쓰는 모든 카드(도감 목록, 기술·특성·타입 상세의 포켓몬 목록, 챔피언스, 홈)에 함께 적용된다.

**3. 타입 상세(`/type-effectiveness/{type}`)로 가는 링크: prefetch를 끈다.** (1.62.4)

- `TypeEffectivenessTable`, `TypeQuickLinks`, `TypeNameLink`, `TypeEffectivenessCta`(타입 상세 링크만), `TypeDetailNav`(타입 목록만)

그 밖의 본문 링크(기술 카드, 챔피언스 탭, 상세 페이지 내부 링크 등)는 기본 prefetch를 유지한다.

## 근거

**비용: 버려지는 요청을 줄인다.** CloudFront는 캐시 적중 여부와 관계없이 요청마다 과금한다. 계정 전체가 무료 한도에 들어가면 이 배포의 월 비용은 약 $12.7에서 $2~3 수준이 된다(요청 과금은 사라지고 Origin Shield·CloudFront Functions·전송 비용이 남는다). 한도에 못 미쳐도 요청 1만 건당 약 $0.012씩 줄어든다. 세 범위를 모두 적용하면 `poke-korea.com` 요청은 최대 약 40% 줄어, 계정 전체가 월 1,100만 건 안팎으로 무료 한도에 근접한다.

**서버 부하: 오리진 요청이 줄어든다.** 캐시를 통과하지 못하고 EC2까지 간 요청의 78%가 RSC다. EC2(t3.small)는 CPU 여유가 크지만(14일 평균 9%) 메모리가 최대 86%까지 올라간다. 2026-08-29에는 서버 리소스 문제로 전체 장애가 있었으므로, 오리진 요청 감소는 안정성에도 도움이 된다.

**링크 성격에 맞춰 방식을 나눈다.**

- **메뉴**: 목적지가 몇 개 페이지로 고정되어 캐시 적중률이 높고, 오리진 응답도 빠르다(ALB 기준 p50 4ms, p90 86ms). 미리 받지 않아도 대기가 짧다.
- **포켓몬 카드**: RSC 요청의 가장 큰 발생원이지만, 도감 탐색은 서비스의 핵심 동선이다. 목적지가 다양해 캐시 Miss가 많고 `loading.tsx`가 없어서, 완전히 끄면 클릭 후 화면 변화 없이 기다리게 된다. 그래서 끄지 않고 **prefetch 시점을 "화면에 보일 때"에서 "누르려 할 때"로 늦춘다.** 터치 시작부터 클릭 확정까지의 시간 동안 데이터를 미리 받기 시작하므로 체감 지연이 작다. 스크롤로 지나치기만 한 카드의 요청은 사라진다. 같은 경로를 여러 번 호출해도 라우터 캐시가 중복 요청을 막는다.
- **타입 상세 링크**: 실제 조회 148건에 RSC 19,904건으로 **요청의 99% 이상이 버려진다.** 목적지는 18개 타입별 정적 페이지라 캐시 적중률이 높고, 상성 계산기의 주 동선도 아니다. 의도 기반 처리까지 할 이유가 없어 끈다.

**SEO: 영향이 없다.** `<Link>`는 서버 HTML에 `<a href>`로 그대로 출력되어 크롤러의 링크 발견에는 변화가 없다. LCP·CLS는 첫 페이지 로딩에서 측정되고, INP는 클릭 후 다음 화면이 그려질 때까지를 측정하므로 데이터 도착 대기는 포함되지 않는다.

## 결과

- 메뉴와 타입 상세 링크는 누른 뒤에 RSC를 요청한다. 캐시가 적중하면 짧은 대기, Miss면 오리진 응답 시간만큼 대기한다. `prefetch={false}`는 hover 때의 prefetch도 끈다(Next.js 15 문서).
- 포켓몬 카드는 터치·hover·포커스 시점에 prefetch한다. 스크롤로 지나친 카드는 요청하지 않는다.
- `PokemonCardShell`이 `next/navigation`의 `useRouter`를 쓰게 되어, 이 카드를 렌더링하는 Storybook story에는 `nextjs.appDirectory: true`가 필요하다.
- 새 링크를 추가할 때도 같은 기준을 따른다. 모든 페이지에 붙는 링크와 거의 열리지 않는 목적지는 `prefetch={false}`, 반복 렌더링되는 핵심 동선 카드는 의도 기반 prefetch.
- 적용 후 1~2주 동안 아래 지표로 효과를 확인한다.
  - CloudFront `Requests`(`E3TRB0VXGC6JWI`)와 Cost Explorer `AP-Requests-Tier2-HTTPS`: 요청·비용 감소
  - ALB `TargetResponseTime`(`poke-korea-group`), CloudWatch Agent `mem_used_percent`: 오리진 부하
  - Search Console Core Web Vitals: UX·SEO 지표 변화
- `/moves/*`(9%), `/champions/*`(6%) 카드는 이번 범위에서 제외했다. 위 지표를 본 뒤 같은 기준으로 검토한다.
