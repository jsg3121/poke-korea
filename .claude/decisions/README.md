# ADR 하네스 — 설치 안내

이 폴더는 **다른 프로젝트에 그대로 복사해서 쓸 수 있는 ADR(아키텍처 의사결정 기록) 하네스**입니다.
규칙 본문은 전부 `index.md`에 있고, CLAUDE.md에는 진입 포인터만 둡니다.

## 설치 (2단계)

### 1. 폴더 복사

대상 프로젝트의 `.claude/decisions/`로 이 폴더를 복사합니다.

```bash
mkdir -p <대상프로젝트>/.claude
cp -R adr-harness <대상프로젝트>/.claude/decisions
```

`records/` 안에 기존 ADR이 들어 있다면 삭제하고, `records/index.md`의 기록 목록 표도 비웁니다.
(배포용 사본은 이미 비어 있습니다.)

### 2. CLAUDE.md에 포인터 추가

대상 프로젝트 루트의 `CLAUDE.md`에 아래 스니펫을 **그대로** 붙여넣습니다.
이 단계를 건너뛰면 폴더는 아무도 읽지 않는 죽은 문서가 됩니다.

```markdown
### 의사결정 기록 (ADR)

새로운 기술적 의사결정이 발생하면 ADR로 기록한다. 작성 규칙·트리거 신호·상태 값·지침 변경 절차는
`.claude/decisions/index.md`가 권위 있는 원본이며, 의사결정 관련 작업 시 반드시 먼저 읽는다.

**IMPORTANT**: 하나의 이슈에 **해결 후보가 2개 이상** 등장하거나, **트레이드오프**를 따지거나,
어떤 방안을 **검토 후 기각**하게 되면 — 논의가 끝나기를 기다리지 말고 **그 시점에 ADR 작성을 제안**한다.
작성 여부는 사용자가 결정하며, 제안 없이 임의로 작성하지 않는다.

기존 지침·컨벤션과 충돌하는 결정을 내릴 때는 `.claude/decisions/index.md`의 "지침 변경 관리" 절차를 따른다.
```

CLAUDE.md의 폴더 구조 다이어그램이 있다면 아래 항목도 함께 추가합니다.

```text
├── decisions/                 # ADR (의사결정 기록)
│   ├── index.md               #   ADR 규칙 (권위 원본)
│   ├── template.md            #   ADR 작성 템플릿
│   └── records/               #   ADR 기록 (index.md = 목록)
```

## 왜 이렇게 나눠져 있는가

Claude Code가 세션 시작 시 자동으로 읽는 것은 `CLAUDE.md`뿐입니다. 하위 문서는 누군가 참조해야 읽힙니다.
따라서 **포인터는 CLAUDE.md에, 규칙 본문은 이 폴더에** 두는 분리가 이식성의 필요조건입니다.
규칙이 CLAUDE.md에 흩어져 있으면 폴더만 복사해도 동작하지 않고, 반대로 포인터가 없으면 폴더가 로드되지 않습니다.

- 참고: [Claude Code — Memory](https://code.claude.com/docs/en/memory)

## 프로젝트 무관 / 프로젝트 고유 구분

| 파일 | 성격 | 복사 시 |
| ------ | ------ | ------ |
| `README.md` | 설치 안내 | 그대로 |
| `index.md` | ADR 규칙 | 그대로 |
| `template.md` | 작성 템플릿 | 그대로 |
| `records/index.md` | 기록 목록 | 표를 비우고 시작 |
| `records/ADR-*.md` | 개별 ADR | 복사하지 않음 |

## 커스터마이징 포인트

- **언어**: 문서가 한국어로 작성되어 있습니다. 영어 프로젝트라면 `index.md`·`template.md`를 번역합니다.
- **상태 값**: `제안 | 승인 | 폐기 | 대체됨` 4종. 팀 워크플로우에 맞춰 `index.md`의 "상태 값" 표에서 조정합니다.
- **트리거 신호**: `index.md`의 "트리거 신호" 표에 프로젝트 특유의 신호를 추가하면 제안 정확도가 올라갑니다.
- **담당 필드**: 1인 프로젝트라면 `template.md`의 `**담당**` 줄을 제거해도 됩니다.
